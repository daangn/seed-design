## Usage

```tsx
import {
  DialogAction,
  DialogBody,
  DialogContent,
  DialogFooter,
  DialogRoot,
  DialogTrigger,
} from "@/components/ui/dialog";
import { ActionButton } from "@seed-design/lynx-react";

export function App() {
  return (
    <DialogRoot size="medium">
      <DialogTrigger>
        <ActionButton variant="neutralSolid">다이얼로그 열기</ActionButton>
      </DialogTrigger>
      <DialogContent title="제목" description="부가 설명">
        <DialogBody>
          <text>본문 콘텐츠</text>
        </DialogBody>
        <DialogFooter>
          <DialogAction variant="neutralSolid">닫기</DialogAction>
        </DialogFooter>
      </DialogContent>
    </DialogRoot>
  );
}
```

`DialogTrigger`는 Content 밖에 두세요. `DialogContent`는 기본으로 헤더 닫기 버튼을 표시하며, `showCloseButton={false}`로 숨길 수 있습니다.

`DialogBody`는 Content의 최대 높이 안에서 세로로 스크롤합니다. `DialogAction`은 탭하면 Dialog를 닫지만, `disabled` 또는 `loading` 상태에서는 닫지 않습니다.

## Examples

### Trigger

`<DialogTrigger>`를 탭하면 Dialog가 열립니다. Lynx는 React의 `asChild`를 지원하지 않으며, Trigger가 자식 요소를 감싸는 native view를 렌더링합니다. Trigger가 버튼 역할과 이름을 노출하고 안쪽 `ActionButton`은 별도 접근성 요소가 되지 않습니다. 이름은 문자열 children에서 만들며 직접 전달한 `accessibility-label`이 우선합니다. raw `<text>` 등에서 텍스트를 파생할 수 없는 경우 이름을 명시하세요.

### `onOpenChange` Details

Lynx의 `onOpenChange`는 변경된 `open` 값만 전달합니다. React 버전의 두 번째 인자인 `details.reason`은 지원하지 않습니다. 닫힘 원인이 필요하면 앱이 소유한 버튼과 Trigger의 이벤트 핸들러에서 원인을 별도 상태로 기록하세요.

#### Confirm Before Close

React 예제처럼 `closeButton`, `escapeKeyDown`, `interactOutside`별로 확인 Dialog를 띄우는 동작은 Lynx에서 지원하지 않습니다. Lynx의 callback만으로는 닫힘 원인을 구분할 수 없으므로, 확인이 필요한 액션은 앱이 소유한 버튼의 핸들러에서 확인 Dialog를 먼저 열고 원본 Dialog의 `open`을 직접 제어하세요.

### Portalled

`container`를 지정하지 않으면 Dialog는 Lynx view 안에 렌더링됩니다. `container="window"`처럼 native container 이름을 지정하면 host 화면까지 덮는 native overlay에 렌더링됩니다. `overlayLevel`은 overlay의 표시 순서를 정합니다.

### Responsive

React의 `ResponsiveDialog`와 같은 자동 전환 컴포넌트는 Lynx에서 제공하지 않습니다. 화면 크기에 따라 `Dialog`와 `BottomSheet`를 앱에서 직접 선택하거나, 동일한 controlled 상태를 두 컴포넌트에 연결하세요.

## 웹 버전과의 차이

- Trigger는 자식을 native `view`로 감싸며 `asChild`를 제공하지 않습니다.
- `onOpenChange`는 닫힌 원인 없이 boolean 값만 전달합니다.
- `DialogBody`는 native scroll view로 렌더링하며, overflow 구분선과 fade mask를 표시하지 않습니다.
- 제목에는 heading 접근성을 적용하지만 Content와 제목을 DOM id로 연결하지 않습니다.
- `container`와 `overlayLevel`로 native overlay의 위치와 표시 순서를 지정합니다.
- `ResponsiveDialog`, `lazyMount`, `unmountOnExit`은 제공하지 않습니다. 반응형 전환이 필요하면 같은 controlled 상태로 Dialog와 Bottom Sheet를 선택하세요.
