## Installation

### Default

순서 변경이 필요하지 않은 경우 기본 snippet을 설치합니다.

```package-install
npx @seed-design/cli@latest add ui:attachment-field
```

<LynxManualInstallation name="attachment-field" />

### Reorderable

네이티브 가로 long-press gesture로 첨부 항목 순서를 변경하려면 별도 snippet을 설치합니다. 기본 snippet에는 reorder gesture가 포함되지 않습니다. 프로젝트에 `@seed-design/lynx-react-sortable` 의존성이 추가됩니다.

```package-install
npx @seed-design/cli@latest add ui:attachment-field-reorderable
```

<LynxManualInstallation name="attachment-field-reorderable" />

<Callout>
  Lynx `AttachmentField`는 브라우저 파일 input을 만들지 않습니다. 호스트가 제공하는 네이티브 파일 선택 adapter를 `onSelectFiles`로 전달해야 합니다. 이 문서의 `fixture://` URI와 고정 이미지는 실행 가능한 picker가 아닌 문서 fixture입니다.
</Callout>

## Usage

`onSelectFiles`의 호스트 adapter는 `NativeFile[]` 또는 `Promise<NativeFile[]>`를 반환합니다. 선택을 취소하면 빈 배열을 반환해야 하며, adapter 오류는 `onSelectError`로 전달됩니다.

```tsx
import { AttachmentField, AttachmentInput } from "@/components/ui/attachment-field";

<AttachmentField
  maxFiles={3}
  label="파일 업로드"
  onSelectFiles={openNativeFilePicker}
  onSelectError={handleFilePickerError}
>
  <AttachmentInput />
</AttachmentField>;
```

`NativeFile`은 `uri`, `name`, `type`, `size`와 선택적인 `previewUrl`로 구성됩니다. `File`, `Blob`, HTML `<input type="file">`, object URL은 사용할 수 없습니다. 이미지 모드에서 `previewUrl`이 없으면 `uri`를 사용하며, 일반 파일 모드에서는 파일 아이콘과 이름·크기를 표시합니다.

`AttachmentInput`은 호스트 adapter가 반환한 파일을 `accept`, `maxFiles`, `minFileSize`, `maxFileSize`, `validate` 조건으로 검증합니다. picker의 MIME filter는 UI를 위한 보조 수단이므로 앱과 업로드 서버에서도 검증해야 합니다. adapter가 빈 배열을 반환하면 목록은 변경되지 않습니다.

## Managing File Status

각 항목은 `pending`, `uploading`, `success`, `error` 상태를 갖습니다. 새 항목은 `pending`으로 시작합니다. 앱은 `onFileAccept`에서 업로드를 시작하고 helper로 진행률과 상태를 갱신합니다. 실제 업로드 API와 재시도 정책은 호스트 앱이 소유합니다.

<LynxComponentExample name="lynx/attachment-field/status">
  ```json doc-gen:file
  { "file": "examples/lynx/attachment-field/status.tsx", "codeblock": true }
  ```
</LynxComponentExample>

- `uploading`: `ProgressCircle`이 표시됩니다. progress가 없으면 indeterminate 상태입니다.
- `error`: `onRetry`가 있으면 재시도 action이 표시됩니다. 재시도할 때 같은 id를 `uploading`으로 바꾸고 업로드를 다시 시작합니다.
- picker가 동기 throw 또는 rejected Promise를 반환하면 `onSelectError`가 호출되고 기존 목록은 유지됩니다.

## Reordering Files

`ui:attachment-field-reorderable`은 브라우저 `dnd-kit` 대신 네이티브 가로 long-press gesture로 목록 순서를 변경합니다. `disabled`와 `readOnly`에서는 정렬할 수 없습니다.

사용자 지정 항목을 렌더링할 때는 `SortableAttachmentInputItem`에 현재 `index`를 전달해야 합니다. 스크린 리더는 항목의 파일 이름, 순서, 업로드 상태를 읽고 앞·뒤 이동과 파일 제거 동작을 제공합니다. error 상태에 `onRetry`가 있으면 재시도 동작도 제공합니다. iOS에서는 항목 내부 버튼 대신 이 사용자 지정 접근성 동작을 사용합니다. `readOnly`에서는 이동과 제거가, `disabled`에서는 이동만 비활성화됩니다.

## Lynx 미지원 기능과 앱 대안

### Dropzone

Lynx는 React `AttachmentDropzone`의 브라우저 drag-and-drop 이벤트와 HTML file input을 지원하지 않습니다. 네이티브 파일 picker는 `onSelectFiles`에 연결하며, 목록 순서 변경에는 `ui:attachment-field-reorderable`을 사용합니다.

### HTML form

Lynx에는 브라우저 `form`, `FormData`, `input[type=file]` 제출 경로가 없습니다. 앱은 `onAcceptedFileEntriesChange` 또는 `onFileAccept`로 상태를 유지하고, submit action에서 `NativeFile[]`를 호스트 upload adapter에 전달합니다. 서버 검증 오류는 Field의 `invalid`와 `errorMessage`에 반영합니다.

### react-hook-form

`react-hook-form`을 사용하는 React 예제는 브라우저 파일 입력과 form 제출 경로에 의존하므로 그대로 실행할 수 없습니다. Lynx에서는 앱 state에 `acceptedFileEntries`와 `onAcceptedFileEntriesChange`를 연결하고, 제출할 때 목록 길이와 업로드 상태를 검증한 뒤 Field 오류 상태를 갱신합니다.

### Browser file APIs

`File`, `Blob`, `FileList`, object URL, `window.alert`는 Native 예제에서 사용할 수 없습니다. 호스트 adapter가 `NativeFile`의 `uri`, metadata, 선택적인 `previewUrl`을 제공해야 합니다. 취소하면 `[]`를 반환하며 선택기 또는 권한 오류는 `onSelectError`로 전달됩니다.
