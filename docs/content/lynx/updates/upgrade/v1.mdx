SEED Lynx 1로 업그레이드하는 방법을 안내합니다. 전체 변경사항은 [Changelog](/lynx/updates/changelog)에서 확인할 수 있습니다.

<Callout type="info">
  이 가이드는 SEED Lynx 0.x에서 SEED Lynx 1로 업그레이드하는 경우를 기준으로 작성했습니다.
</Callout>

## AI로 마이그레이션하기

AI 코딩 도구에 아래 프롬프트를 붙여넣으면 이 가이드를 기준으로 프로젝트를 점검하고 코드를 수정할 수 있습니다.

```text title="마이그레이션 프롬프트"
이 프로젝트의 SEED Lynx를 0.x에서 1로 업그레이드해줘.
기준 문서: https://seed-design.io/llms/lynx/updates/upgrade/v1.txt
세부 변경 사항은 이 문서에서 확인하고, 문서와 이 지시가 다르면 문서를 따라줘.

1. 현재 상태 확인
   - package.json에서 @seed-design/lynx-* 패키지와 버전을 정리해줘.
   - seed-design.json의 path 아래 설치된 Lynx snippet 목록을 정리해줘.
   - 작업 전에 커밋되지 않은 변경이 있으면 알려주고 멈춰줘.

2. 패키지 업그레이드
   - 문서의 "패키지 업그레이드" 표에서 프로젝트가 쓰는 패키지만 한 번에 올려줘.
   - 쓰지 않는 headless 패키지는 새로 설치하지 마.
   - 프로젝트의 패키지 매니저를 그대로 사용해줘.

3. 확인 목록 작성
   - "디자인 변경사항이 있는 항목"과 "동작이 바뀌는 항목"의 사용처를 찾아
     파일 위치와 확인할 내용을 적어줘. 이 단계에서는 코드를 수정하지 마.

4. Snippet 업데이트
   - 설치된 항목만 `npx @seed-design/cli@latest add ui:<id> --on-diff backup`으로 다시 설치해줘.
   - legacy 백업과 새 파일을 비교해 사용자 정의 스타일과 동작만 새 파일에 다시 적용해줘.
   - 문서가 1.0 변경이라고 설명한 차이는 백업에서 가져오지 마.

5. 코드 수정
   - "코드 수정이 필요한 항목"을 Step 순서대로 진행해줘.
   - 각 항목의 "수정 대상" 검색어를 모두 검색하고, 사용처가 없으면 검색어와 함께 보고해줘.
   - 같은 Step 안의 독립된 항목은 subagent로 병렬 처리해줘.
   - 여러 항목이 같은 파일을 수정하면 한 subagent가 그 파일을 맡게 해줘.
   - import뿐 아니라 CSS 클래스와 CSS 변수 문자열도 검색해줘.

6. 검증
   - 타입 검사와 빌드를 실행해줘. prop이나 타입 선언을 지워서 문제를 숨기지 마.
   - 각 항목의 "작업 후 확인"을 수행하고 화면과 상호작용을 점검해줘.
   - `npx @seed-design/cli@latest compat`을 실행해줘.

7. 결과 보고
   - 수정한 파일과 항목, 건너뛴 항목, snippet에 다시 적용한 사용자 정의,
     검증 결과, 디자인·동작 확인 목록, 해결하지 못한 문제를 정리해줘.
```

## 패키지 업그레이드

프로젝트에서 사용하는 패키지만 아래 버전 이상으로 업그레이드하세요.

| --- | --- | --- |
| `@seed-design/lynx-react` | `1.0.0` | `@seed-design/lynx-css`와 함께 올립니다. |
| `@seed-design/lynx-css` | `1.0.0` | `lynx-react` 1.x가 요구하는 범위는 `^1.0.0`입니다. |
| `@seed-design/lynx-react-image` | `1.0.0` | 직접 설치한 경우에만 해당합니다. |
| `@seed-design/lynx-react-toggle` | `1.0.0` | 직접 설치한 경우에만 해당합니다. |
| `@seed-design/lynx-react-use-controllable-state` | `1.0.0` | 직접 설치한 경우에만 해당합니다. |
| `@seed-design/lynx-react-use-press-tap` | `1.0.0` | 직접 설치한 경우에만 해당합니다. |
| `@seed-design/tailwind3-plugin` | `3.0.2` | Tailwind 3 연동을 쓰는 경우에만 해당합니다. Lynx CSS 1.x를 허용합니다. |
| `@seed-design/tailwind4-theme` | `3.0.2` | Tailwind 4 연동을 쓰는 경우에만 해당합니다. Lynx CSS 1.x를 허용합니다. |

## Snippet 업데이트

**수정 대상:** 아래 snippet을 설치한 프로젝트입니다. 패키지를 올려도 프로젝트에 복사된 snippet은 자동으로 바뀌지 않습니다.

아래 명령에서 설치하지 않은 항목은 빼고 실행하세요.

```bash
npx @seed-design/cli@latest add ui:alert-dialog ui:attachment-display-field ui:attachment-display-field-reorderable ui:attachment-field ui:attachment-field-reorderable ui:bottom-sheet ui:callout ui:dialog ui:field-button ui:help-bubble ui:list ui:menu ui:menu-sheet ui:page-banner ui:progress-circle ui:quantity-picker ui:radio-group ui:select ui:select-box ui:slider ui:switch ui:text-field --on-diff backup
```

`ui:swipeable-menu-sheet`은 `ui:menu-sheet`으로 바뀌었습니다. 새 snippet을 설치하고 호출부를 옮긴 뒤 옛 파일을 삭제하세요.

| Snippet | 1.0에서 반영된 차이 |
| --- | --- |
| `ui:menu-sheet`, `ui:field-button` | `MenuSheet*`, `FieldButton*` 공개 이름과 `controlRef`를 사용합니다. |
| `ui:radio-group`, `ui:select-box` | `RadioGroupField.Root`가 상태를 소유하고 Item이 `weight`, `size`, `tone`을 소유합니다. RadioSelectBox의 바깥 Field root와 안쪽 grid도 분리됩니다. |
| `ui:switch` | `Switchmark`가 독립 Root가 아니라 `Switch.Root` 안의 Control과 Thumb이 됩니다. |
| `ui:menu`, `ui:select` | Positioner, Content, ScrollArea를 조합하고 `container`, `overlayLevel`을 전달합니다. |
| `ui:slider` | Thumb, ValueIndicatorRoot, ValueIndicatorLabel에 `thumbIndex`를 전달합니다. |
| `ui:progress-circle`, `ui:quantity-picker` | Range 앞에 Track을 렌더합니다. |
| `ui:attachment-field`, `ui:attachment-display-field` | error icon에 제거된 PrefixIcon `size`, `color` 대신 `Icon`을 사용합니다. |
| `ui:attachment-field-reorderable`, `ui:attachment-display-field-reorderable` | 로컬 `attachment-sortable` helper 대신 1.0의 Sortable package를 사용하고 이동, 삭제, 재시도 접근성 action을 제공합니다. |

| Snippet | 1.0에서 반영된 차이 |
| --- | --- |
| `ui:alert-dialog`, `ui:dialog` | disabled 또는 loading인 Action이 dialog를 닫지 않습니다. Dialog의 새 native prop 계약도 따릅니다. |
| `ui:bottom-sheet` | Content가 `container`, `overlayLevel`을 Positioner에 전달합니다. |
| `ui:help-bubble` | Trigger와 Anchor가 `container`, `overlayLevel`을 Positioner에 전달합니다. |
| `ui:callout` | handler가 없는 ActionableCallout도 button semantics와 press feedback을 가집니다. |
| `ui:list` | ListDivider의 명시적인 `accessibility-element` 값을 보존합니다. |
| `ui:page-banner` | handler가 없는 ActionablePageBanner도 button semantics와 press feedback을 가집니다. |
| `ui:text-field` | wrapper가 내부에서 소유하는 `nativeInsertionMaxLength`를 공개 prop에서 제외합니다. |

`--on-diff backup`은 기존 파일을 `legacy-<파일명>-<타임스탬프>.tsx`로 옮기고 새 파일을 씁니다. 위 목록의 차이는 1.0 변경이므로 옛 구현을 새 파일에 되돌리지 마세요. 그 밖의 차이는 프로젝트의 사용자 정의이거나 오래된 snippet과 최신 0.x snippet 사이의 차이입니다. 필요한 사용자 정의만 새 파일에 다시 적용한 뒤 legacy 파일을 삭제하세요.

`compat`은 snippet이 요구하는 패키지 버전을 검사하지만 파일 내용이 최신인지는 확인하지 않습니다.

</Step>

## 코드 변경

### 디자인 변경사항이 있는 항목

화면 결과를 확인하고, 기존 화면을 유지해야 할 때만 별도 스타일을 적용하세요.

1. `HStack`과 `VStack`의 `gap`이 줄과 열 양쪽에 적용됩니다. 줄바꿈한 `HStack`은 행 간격이, 줄바꿈한 `VStack`은 열 간격이 생깁니다. 기존 결과를 유지하려면 각각 `rowGap: "0px"`, `columnGap: "0px"`을 명시하세요.
2. [Segmented Control](/lynx/components/segmented-control), [Badge](/lynx/components/badge), [Reaction Button](/lynx/components/reaction-button)의 눌림 효과가 Main Thread 상태와 `:active`를 사용합니다. 직접 recipe의 `pressed`를 조작하던 코드는 아래 코드 변경 절을 따르세요.
3. [App Bar](/lynx/components/app-bar)의 IconButton에 눌림 배경, 색상 전환, `r2` radius가 적용됩니다. 배경이나 radius를 덮어쓴 화면을 확인하세요.
4. [Floating Action Button](/lynx/components/floating-action-button)의 접힌 Label은 제거되지 않고 opacity로 전환됩니다. Label은 한 줄로 유지되며 접근성 트리에서는 숨겨집니다.
5. Sheet Footer와 mark 정렬이 바뀌었습니다. BottomSheet Body는 남는 높이를 채우지 않고 내용 크기로 배치됩니다. List와 SelectBox의 checkbox/radio mark는 중앙에 맞고, MenuSheet divider는 각 Item 안쪽에 놓입니다. Attachment remove button에는 눌림 scale이 적용됩니다.

[Tabs](/lynx/components/tabs)의 Indicator는 하단 stroke와 겹치도록 1px 아래에 배치됩니다. 이를 보정하려고 직접 지정한 `bottom: -1px`이 있다면 제거하고 결과를 확인하세요. Checkbox의 ghost mark는 선택 상태용 배경을 따로 사용하며 indeterminate 기본 접근성 값은 `mixed`입니다.

#### 1. 이름과 최상위 구조 먼저 변경

##### SwipeableMenuSheet를 MenuSheet로 변경

**수정 대상:** `SwipeableMenuSheet`, `SwipeableMenuSheetCloseReason`, `swipeable-menu-sheet`

```tsx
import {
  SwipeableMenuSheet, // [!code --]
  type SwipeableMenuSheetCloseReason, // [!code --]
  MenuSheet, // [!code ++]
  type MenuSheetOpenChangeReason, // [!code ++]
} from "@seed-design/lynx-react";

{/* [!code --] */}
<SwipeableMenuSheet.Root>{children}</SwipeableMenuSheet.Root>
{/* [!code ++] */}
<MenuSheet.Root>{children}</MenuSheet.Root>
```

모든 prefixed part와 Props 타입도 `MenuSheet*`로 바꾸세요. CSS recipe 이름 `menuSheet`과 `seed-menu-sheet-*`는 그대로입니다.

**변경하지 않으면:** 1.0에는 옛 export가 없습니다.

**작업 후 확인:** 옛 이름과 옛 snippet import가 남지 않았는지 검색하세요.

##### InputButton을 FieldButton으로 변경

**수정 대상:** `InputButton`, `InputButtonRoot`, `inputButtonRef`, `@seed-design/lynx-css/recipes/input-button`, `inputButton`, `seed-input-button__`

```tsx
import { InputButton } from "@seed-design/lynx-react"; // [!code --]
import { FieldButton } from "@seed-design/lynx-react"; // [!code ++]

{/* [!code --] */}
<InputButton.Root>{children}</InputButton.Root>
{/* [!code ++] */}
<FieldButton.Root>{children}</FieldButton.Root>
```

Registry `ui:field-button` wrapper의 ref prop도 바꿉니다.

```tsx
import { FieldButton } from "@/components/ui/field-button";

{/* [!code --] */}
<FieldButton inputButtonRef={rootRef} />
{/* [!code ++] */}
<FieldButton controlRef={rootRef} />
```

Recipe와 class 이름도 `field-button`으로 바뀌었습니다. `@seed-design/lynx-css/recipes/input-button`을 직접 import하거나 `.seed-input-button__*` selector로 스타일을 덮어썼다면 함께 바꾸세요. `FieldButton` 컴포넌트만 쓴다면 바꿀 것이 없으며, 스타일 값은 그대로입니다.

```tsx
import { inputButton, type InputButtonVariantProps } from "@seed-design/lynx-css/recipes/input-button"; // [!code --]
import { fieldButton, type FieldButtonVariantProps } from "@seed-design/lynx-css/recipes/field-button"; // [!code ++]

const classes = inputButton({ size: "medium" }); // [!code --]
const classes = fieldButton({ size: "medium" }); // [!code ++]
```

`inputButtonVariantMap`은 `fieldButtonVariantMap`으로, `.seed-input-button__root` 같은 selector는 `.seed-field-button__root`로 바꾸세요.

**변경하지 않으면:** 1.0에는 `InputButton*` export와 `@seed-design/lynx-css/recipes/input-button`이 없고, `.seed-input-button__*` selector는 더 이상 어떤 요소에도 적용되지 않습니다.

**작업 후 확인:** ClearButton을 `values`와 `onValuesChange`로 제어한다면, 옛 `bindtap`에서도 같은 상태를 두 번 바꾸지 않는지 확인하세요.

##### KeyboardAvoidingScrollView를 Root와 Content로 분리

**수정 대상:** `KeyboardAvoidingScrollViewProps`, `<KeyboardAvoidingScrollView`, 해당 컴포넌트의 ref, scroll prop과 event

```tsx
import type { KeyboardAvoidingScrollViewProps } from "@seed-design/lynx-react"; // [!code --]
import type { // [!code ++]
  KeyboardAvoidingScrollViewRootProps, // [!code ++]
  KeyboardAvoidingScrollViewContentProps, // [!code ++]
} from "@seed-design/lynx-react"; // [!code ++]

{/* [!code --] */}
<KeyboardAvoidingScrollView
  ref={scrollRef} // [!code --]
  keyboardGap={24} // [!code --]
  style={{ height: "100%", padding: "20px" }} // [!code --]
  scroll-bar-enable={false} // [!code --]
  bindscroll={handleScroll} // [!code --]
// [!code --]
>
  {/* [!code --] */}
  {fields}
{/* [!code --] */}
</KeyboardAvoidingScrollView>
{/* [!code ++] */}
<KeyboardAvoidingScrollView.Root keyboardGap={24} style={{ height: "100%" }}>
  {/* [!code ++] */}
  <KeyboardAvoidingScrollView.Content
    ref={scrollRef} // [!code ++]
    style={{ padding: "20px" }} // [!code ++]
    scroll-bar-enable={false} // [!code ++]
    bindscroll={handleScroll} // [!code ++]
  // [!code ++]
  >
    {/* [!code ++] */}
    {fields}
  {/* [!code ++] */}
  </KeyboardAvoidingScrollView.Content>
{/* [!code ++] */}
</KeyboardAvoidingScrollView.Root>
```

Root에는 `keyboardGap`, `scrollBehavior`, 바깥 높이를 둡니다. Content에는 padding, scroll ref, scroll prop과 event를 둡니다. 키보드 위에 고정할 버튼은 새 `KeyboardAvoidingScrollView.Footer`에 놓을 수 있습니다.

**변경하지 않으면:** 옛 단일 컴포넌트와 `KeyboardAvoidingScrollViewProps` export가 없습니다. scroll ref나 event를 Root에 두면 실제 scroll host를 가리키지 않습니다.

**작업 후 확인:** 입력 focus 시 Content가 스크롤되고 Footer를 쓴 화면에서는 Footer가 키보드 위에 놓이는지 확인하세요.

##### Chip.Root를 Chip.Button으로 변경

**수정 대상:** `Chip.Root`, `ChipRoot`, `Chip.RootProps`, `ChipRootProps`

```tsx
import { ChipRoot, type ChipRootProps } from "@seed-design/lynx-react"; // [!code --]
import { ChipButton, type ChipButtonProps } from "@seed-design/lynx-react"; // [!code ++]

{/* [!code --] */}
<Chip.Root bindtap={handleTap}>라벨</Chip.Root>
{/* [!code ++] */}
<Chip.Button bindtap={handleTap}>라벨</Chip.Button>
```

**변경하지 않으면:** 옛 export와 namespace member가 없습니다.

**작업 후 확인:** 모든 일반 Chip이 `Chip.Button`을 쓰는지 확인하세요.

#### 2. 상태 소유권과 component anatomy 변경

##### RadioGroup 상태를 RadioGroupField.Root로 이동

**수정 대상:** `RadioGroup.Root`, `RadioGroupRoot`, root의 `value`, `onValueChange`, `disabled`, `weight`, `size`, `tone`, `RadioSelectBoxRoot`

```tsx
{/* [!code --] */}
<RadioGroup.Root value={value} onValueChange={setValue} size="large" tone="neutral">
  {/* [!code --] */}
  <RadioGroup.Item value="a">A</RadioGroup.Item>
{/* [!code --] */}
</RadioGroup.Root>
{/* [!code ++] */}
<RadioGroupField.Root value={value} onValueChange={setValue}>
  {/* [!code ++] */}
  <RadioGroup.Root>
    {/* [!code ++] */}
    <RadioGroup.Item value="a" size="large" tone="neutral">A</RadioGroup.Item>
  {/* [!code ++] */}
  </RadioGroup.Root>
{/* [!code ++] */}
</RadioGroupField.Root>
```

표시용 `RadioGroup.Root`는 layout만 담당합니다. Field UI가 필요 없다면 `@seed-design/lynx-react-radio-group`의 headless Root를 상태 owner로 사용할 수 있습니다. List radio row와 RadioSelectBox도 stateful ancestor 아래에 두세요.

**변경하지 않으면:** 표시용 Root가 selection과 disabled 상태를 제공하지 않습니다.

**작업 후 확인:** 선택 변경, disabled, validation message와 Item별 size/tone을 확인하세요.

##### Switchmark를 Switch.Root 안으로 이동

**수정 대상:** registry의 `Switchmark`, `SwitchmarkProps`, Switchmark에 전달한 `checked`, `defaultChecked`, `onCheckedChange`, `disabled`

```tsx
{/* [!code --] */}
<Switchmark checked={checked} onCheckedChange={setChecked} />
{/* [!code ++] */}
<Switch.Root checked={checked} onCheckedChange={setChecked}>
  {/* [!code ++] */}
  <Switchmark />
{/* [!code ++] */}
</Switch.Root>
```

**변경하지 않으면:** 1.0 Switchmark는 Control과 Thumb만 렌더하며 Root의 context가 필요합니다.

```tsx
<ReactionButton
  onPressedChange={(next) => { // [!code ++]
    setPressed(next); // [!code ++]
    afterToggle(next); // [!code ++]
  }} // [!code ++]
// [!code ++]
>
  {/* [!code ++] */}
  좋아요
{/* [!code ++] */}
</ReactionButton>
```

선택값이 필요한 Chip.Toggle 작업은 `onCheckedChange(next)`로, Chip.RadioItem 작업은 상위 Chip.RadioRoot의 `onValueChange(next)`로 옮기세요. ReactionButton의 기본 접근성은 toggle button과 `pressed`/`not pressed`, Chip.Toggle의 기본 role은 checkbox입니다.

2. **Sheet open reason과 overlay.** [Bottom Sheet](/lynx/components/bottom-sheet)와 [Menu Sheet](/lynx/components/menu-sheet)의 `onOpenChange`는 `trigger`, `closeButton`, `interactOutside`, `drag` reason을 전달합니다. ref 호출과 controlled `open` prop 변경은 callback을 알리지 않습니다. [Help Bubble](/lynx/components/help-bubble)의 outside tap은 bubble을 닫으면서 아래 element에도 전달됩니다. Arrow 없는 custom bubble은 같은 간격을 유지하려면 `gutter={oldGutter + 8}`을 사용하세요. Menu와 Select는 Positioner의 `container` 선택에 따라 native Back과 `dismiss` 동작이 달라집니다.

3. **접근성 기본값.** Dialog.Title은 heading입니다. CheckSelectBox와 List Checkbox는 `checked`/`not checked`/`mixed`, List Switch는 `checked`/`not checked`, List Radio는 `selected`/`not selected`, Chip.RadioRoot는 `radiogroup`이 기본입니다. List selection row는 하나의 접근성 element가 되며, enabled row의 기본 button trait는 없어집니다. ActionButton은 disabled 또는 loading일 때 `disabled` trait를 사용하고, FloatingActionButton과 ContextualFloatingButton은 enabled 상태에서 button trait를 사용합니다. PrefixIcon, SuffixIcon과 입력 slot icon은 기본적으로 장식용으로 숨겨집니다. 예전 안내 문구가 제품 요구사항인 경우에만 명시적인 접근성 prop으로 유지하세요.

4. **layout과 자식 분류 수정.** Divider는 orientation이나 inset이 바뀌면 view를 remount하고 ref를 다시 연결합니다. TagGroup은 falsy child를 제외하고 separator를 접근성 트리에서 숨깁니다. Fragment 안의 MannerTempEmote도 emote slot으로 분류됩니다. 처음 열린 Accordion content와 SelectBox Footer는 0px에서 올라오는 animation 없이 표시됩니다. Tabs와 ChipTabs carousel은 page나 disabled trigger가 바뀌어도 현재 selection을 유지하며, 실제 swipe만 selection을 바꿉니다. 구형 Lynx Engine에서도 TextField의 초기 `value`와 `defaultValue`를 native input에 동기화합니다.

5. **Registry wrapper 기본 동작.** ActionablePageBanner와 ActionableCallout은 application handler가 없어도 button semantics와 press feedback을 가집니다. 정보 표시용이면 non-actionable wrapper를 사용하세요. Dialog와 AlertDialog의 disabled/loading Action은 닫힘을 요청하지 않고, ListDivider는 명시적인 `accessibility-element` 값을 보존합니다.

MenuSheet의 custom item recipe는 divider를 Item의 다음 sibling이 아니라 Item 내부에 배치합니다.

```tsx
{/* [!code --] */}
<view className={classes.root}>{content}</view>
{/* [!code --] */}
<view className={classes.divider} />
{/* [!code ++] */}
<view className={classes.root}>
  {/* [!code ++] */}
  {content}
  {/* [!code ++] */}
  <view className={classes.divider} />
{/* [!code ++] */}
</view>
```

BottomSheet와 MenuSheet의 overlay container, HelpBubble의 `container`와 `overlayLevel`처럼 snippet이 새로 전달하는 prop도 재설치한 wrapper에서 확인하세요.

</Step>

</Steps>

## 새로 추가된 컴포넌트

SEED Lynx 1.0에는 프로필 이미지, 빈 콘텐츠 영역, 콘텐츠 이미지를 위한 세 컴포넌트가 추가됩니다. 기존 코드의 필수 마이그레이션 항목은 아니며, 필요한 화면에서 선택해 사용하세요.

아래 컴포넌트는 모두 `@seed-design/lynx-react@1.0.0`과 `@seed-design/lynx-css@1.0.0`부터 제공합니다. **SEED 패키지 버전과 Lynx Engine 버전은 별개**입니다. 앱에 포함된 Engine이 사용할 컴포넌트의 최소 버전을 만족하는지 확인하세요.

| 컴포넌트 | 최소 Lynx Engine | 용도·제공 방식 |
| --- | --- | --- |
| Avatar | `3.6` | 프로필 이미지, fallback, 배지와 AvatarStack을 제공합니다. `ui:avatar` snippet을 설치합니다. |
| Content Placeholder | `3.6` | 이미지가 없거나 로딩 전인 영역에 프리셋 또는 커스텀 에셋을 표시합니다. `ui:content-placeholder` snippet을 설치합니다. |
| Image Frame | `3.9` | 이미지 비율·모서리·테두리·fallback과 배지·아이콘·좋아요 버튼 오버레이를 제공합니다. `@seed-design/lynx-react`에서 직접 import합니다. |

Avatar와 Content Placeholder는 사용할 snippet만 설치하세요. Image Frame은 별도 snippet 설치가 필요하지 않습니다.

```bash
npx @seed-design/cli@latest add ui:avatar ui:content-placeholder
```

- **Avatar:** `badgeMask`로 원·꽃·방패 모양의 투명한 여백을 만들고, `AvatarBadge`의 자식으로 배지 에셋을 넣습니다. 자식의 윤곽을 자동으로 분석하지 않으므로 다른 모양의 커스텀 배지는 `badgeMask="none"`을 사용하세요. 마스크를 위한 플랫폼별 스타일은 컴포넌트가 처리합니다.
- **Content Placeholder:** React와 같은 12개 프리셋과 light/dark 에셋을 제공합니다. 아이콘이나 이미지를 `children`으로 넣으면 프리셋을 대체합니다. 커스텀 에셋의 색은 유지되며, 모노크롬 아이콘의 색은 자식의 `tint-color`로 지정하세요.
- **Image Frame:** `ImageFrameFloater`로 오버레이 위치를 지정하고, `ImageFrameReactionButton`의 `pressed`·`onPressedChange`로 좋아요 상태를 제어할 수 있습니다. Engine 3.6에서는 비율 기반 레이아웃과 콘텐츠 표시 문제가 확인되어 지원하지 않습니다.

Avatar와 Image Frame은 headless Image로 로딩 상태를 처리합니다. 앱에서 headless 패키지를 따로 설치할 필요는 없습니다. 두 컴포넌트 모두 이미지 로딩이 성공하면 fallback을 언마운트하므로, 다시 표시할 때 유지할 상태는 부모에서 관리하세요. 자세한 사용법과 React와의 차이는 각 컴포넌트 문서에서 확인할 수 있습니다.
