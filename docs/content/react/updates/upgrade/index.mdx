SEED 패키지(`@seed-design/react`, `@seed-design/css` 등)의 버전을 올릴 때 호환성을 확인하고 안전하게 업그레이드하는 방법을 안내합니다.

세부 변경 목록은 업그레이드하려는 목표 버전에 맞춰 확인하세요.

## 버저닝 정책

SEED는 **2.0을 분기점**으로 버저닝 정책이 다릅니다.

| 구간 | 정책 |
| --- | --- |
| **2.0 이상** | strict SemVer를 따릅니다. breaking change는 **major에서만** 발생하고, minor·patch는 하위 호환을 보장합니다. |
| **2.0 미만 (0.x·1.x)** | minor·patch에서도 breaking이 있을 수 있었습니다. 이 구간은 아래 **호환성** 섹션의 방법으로 실제 호환 범위를 확인합니다. |

<Callout>
2.0 이상에서는 같은 major 안에서 minor·patch를 자유롭게 올릴 수 있습니다. 1.x 구간을 올릴 때 호환성 확인이 특히 중요합니다.
</Callout>

<Callout type="warn">

`@seed-design/css/vars/component/typography`를 제외한 `@seed-design/css/vars/component/*` 경로는 SemVer 보장 대상이 아닙니다. rootage component spec이 바뀌면 minor·patch에서도 이름이나 구조가 바뀔 수 있으므로 앱·라이브러리 코드에서 직접 의존하지 않는 것을 권장합니다.

</Callout>

## 호환성: react ↔ css

`@seed-design/react`는 `@seed-design/css`를 런타임 기반(클래스네임·스타일)으로 사용합니다. **두 패키지를 호환되지 않는 버전으로 섞으면 클래스네임이 어긋나 스타일이 깨질 수 있습니다.**

- **2.0 이상**: `react`가 `peerDependencies`로 호환되는 `css` 범위(`^N.M.0`)를 선언합니다. 선언을 따르면 안전합니다.
- **2.0 미만**: 선언이 불완전하거나 같은 minor끼리 맞춰 릴리즈(lockstep)되던 구간이 있어, CLI가 호환성 매니페스트로 실제 호환 범위를 판단합니다.

### 호환성 확인하기

설치된 조합이 맞는지 `compat`으로 확인합니다.

```bash
npx @seed-design/cli@latest compat
```

- 설치된 `react`·`css`의 **실제 버전**을 읽어 서로 호환되는지 검사하고, 안 맞으면 어느 버전으로 올려야 하는지 알려줍니다.
- 호환 이슈가 있으면 종료 코드 `1`로 끝나므로 CI 게이트로도 쓸 수 있습니다.

올리기 **전에** 특정 버전 조합이 호환되는지 미리 확인하려면 `--with`를 사용합니다.

```bash
npx @seed-design/cli@latest compat --with react@2.0.0 --with css@2.0.0
```

스크립트나 도구에서 쓸 JSON 출력은 `--json`을 사용합니다.

```bash
npx @seed-design/cli@latest compat --json
```

## 버전 올리기

<Steps>

<Step>
### 현재 호환 상태 확인

```bash
npx @seed-design/cli@latest compat
```

지금 설치된 조합에 문제가 없는지 먼저 확인합니다.
</Step>

<Step>
### 변경사항 확인

목표 버전까지 무엇이 바뀌는지(특히 breaking change) 확인합니다.

```bash
npx @seed-design/cli@latest docs react/updates/changelog/react/{현재버전} --raw
```

이 명령은 **현재 버전 이후 최신까지** 모든 변경사항을 반환합니다. 특정 목표 버전까지만 보려면 그보다 높은 버전 섹션은 건너뛰세요.
</Step>

<Step>
### react와 css를 호환되는 조합으로 올리기

<Callout type="warn">
1.x 구간을 넘나들 때는 `react`와 `css`를 **호환되는 버전으로 함께** 올려야 합니다. 한쪽만 올리면 스타일이 깨질 수 있습니다.
</Callout>

```package-install
@seed-design/react@{목표버전} @seed-design/css@{목표버전}
```
</Step>

<Step>
### snippet 재설치

일부 버전 경계에서는 내부 구조 변경으로 snippet 재설치가 필요합니다. 변경사항에 "재설치 필요"로 표시된 컴포넌트는 다시 받습니다.

```bash
npx @seed-design/cli@latest add ui:{component}
```
</Step>

<Step>
### 검증

업그레이드 후 다시 `compat`으로 호환을 확인하고, 화면 스타일과 동작을 점검합니다.
</Step>

</Steps>

<Callout>
복잡한 버전 점프나 여러 패키지를 한 번에 올릴 때는 Claude Code 등에서 `/seed-design` 스킬에게 "현재 버전에서 X로 업그레이드하고 싶어"라고 요청하면 호환 진단, 업그레이드 경로, 재설치할 snippet 목록을 정리해 줍니다.
</Callout>
