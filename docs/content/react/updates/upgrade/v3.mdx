SEED React 3으로 업그레이드하는 방법을 안내합니다. 신규 기능 등 전체 변경사항은 [Changelog](/react/updates/changelog)에서 확인할 수 있습니다.

<Callout type="info">
  이 가이드는 `2.x`에서 `3`으로 업그레이드하는 경우를 기준으로 작성되었습니다.
  2보다 낮은 버전을 사용 중이라면 [SEED React 2](/react/updates/upgrade/v2)
  가이드를 따른 뒤 이 문서로 돌아와 주세요.
</Callout>

## AI로 마이그레이션하기

AI 코딩 도구(예: Claude Code)에 아래 프롬프트를 붙여넣으면 이 가이드를 읽고 프로젝트를 점검한 뒤 코드 수정이 필요한 항목을 적용합니다. 코드 블록 오른쪽 위 버튼으로 복사할 수 있습니다. 화면이 달라지는 디자인 변경 항목은 AI가 직접 결정하지 않고 확인이 필요한 목록으로 정리하도록 요청합니다.

```text title="마이그레이션 프롬프트"
이 프로젝트의 SEED React를 2.x에서 3으로 업그레이드해줘.
기준 문서: https://seed-design.io/llms/react/updates/upgrade/v3.txt
세부 변경 사항은 이 문서에서 확인하고, 문서와 이 지시가 다르면 문서를 따라줘.

1. 현재 상태 확인
   - package.json에서 @seed-design/* 패키지와 버전을 정리해줘.
   - seed-design.json의 path 아래 설치된 snippet 목록을 정리해줘.
   - 작업 전에 커밋되지 않은 변경이 있으면 알려주고 멈춰줘.

2. 패키지 업그레이드
   - 문서의 "패키지 업그레이드" 표에서 이 프로젝트가 쓰는 패키지만
     최소 버전 이상으로 올려줘. 쓰지 않는 패키지는 새로 설치하지 마.
   - 프로젝트의 패키지 매니저를 그대로 사용해줘.

3. 코드 수정
   - 문서의 "Snippet 업데이트"와 "코드 수정이 필요한 항목"을 확인하고,
     각 "수정 대상"에 해당하는 사용처를 문서의 변경 후 코드로 바꿔줘.
   - import뿐 아니라 하드코딩한 CSS 클래스와 CSS 변수도 문자열로 검색해줘.
   - snippet을 다시 설치할 때는
     `npx @seed-design/cli@latest add --on-diff backup ui:<id>`를 사용해줘.
     이 옵션은 기존 파일을 legacy-* 파일로 옮기고 새 snippet을 쓰므로
     백업만으로는 커스터마이즈가 유지되지 않아. 백업 파일과 새 파일을 비교해
     필요한 사용자 정의 스타일·동작을 새 snippet에 다시 적용해줘.

4. 디자인 변경과 동작 변화는 수정하지 말고 목록만 만들어줘
   - 문서의 "디자인 변경사항이 있는 항목"과 "동작이 바뀌는 항목"에
     해당하는 사용처를 찾아 파일 위치와 확인할 내용을 적어줘.

5. 검증
   - 타입 검사와 빌드를 실행하고 실패를 해결해줘.
   - `npx @seed-design/cli@latest compat`으로 snippet 호환성을 확인해줘.

6. 결과 보고
   - 바꾼 파일과 항목, snippet에 다시 적용한 사용자 정의와 적용하지 않은 것,
     실행한 검증 결과, 4번의 확인 필요 목록, 해결하지 못한 문제를 정리해줘.
```

## Snippet 업데이트

**수정 대상:** 아래 명령에 나열된 snippet을 사용하는 프로젝트입니다. 해당 snippet을 사용하지 않는다면 이 단계를 건너뛰세요.

이번 버전에서는 `@seed-design/react/primitive` import 경로를 제거하고, Chip·List 등의 API를 변경했습니다. 기존 snippet에도 이 경로와 API를 사용하는 코드가 있습니다. snippet은 프로젝트에 복사된 파일이므로 패키지만 업그레이드해도 자동으로 바뀌지 않습니다.

아래 명령에서 프로젝트에 설치하지 않은 항목은 빼고 실행하세요. 최신 snippet에는 새 import 경로와 API가 반영되어 있습니다.

```package-install
npx @seed-design/cli@latest add ui:attachment-display-field ui:attachment-display-field-reorderable ui:attachment-field ui:attachment-field-reorderable ui:chip ui:list ui:pagination ui:side-navigation ui:table-pagination block:side-navigation-02 --on-diff backup
```

`--on-diff backup`은 기존 파일과 내용이 다르면 같은 폴더에 `legacy-파일명-타임스탬프.tsx` 형태로 백업한 뒤 새 파일을 받습니다. 프로젝트에 맞게 수정했던 내용은 백업 파일과 비교해 새 파일에 다시 적용하세요. 백업 파일에는 이전 import가 남으므로, 변경을 옮긴 후 정리하세요.

기존 파일을 백업 없이 덮어쓰려면 `--on-diff overwrite`를 사용하세요. `--on-diff`를 생략하면 파일마다 차이를 확인하고 백업·덮어쓰기·건너뛰기를 선택할 수 있습니다.

**Chip의 `ChipBaseProps`를 import했다면 사용처도 수정하세요.** 이 타입은 snippet 내부에서 공통 스타일 props를 선택 상태 props와 합치기 위해 사용했습니다. 이제 각 컴포넌트의 타입에 필요한 props가 모두 포함되어 별도 공통 타입을 제거했습니다. 자신의 코드에서 `ChipBaseProps`를 가져오던 경우에는 같은 snippet의 `ButtonChipProps`, `ToggleChipProps`, `RadioChipItemProps` 중 사용하는 컴포넌트에 맞는 타입으로 바꾸세요.

</Step>

## 코드 변경

### 디자인 변경사항이 있는 항목

화면에 보이는 결과가 달라질 수 있어 디자인 결정이 필요할 수 있는 항목입니다.

#### 1. `$color.bg.neutral-solid` 색상 변경

<Badge tone="critical">직접 판단 필요</Badge>

`$color.bg.neutral-solid`가 라이트 모드에서 `gray-1000`에서 `gray-900`으로, 다크 모드에서 `gray-300`에서 `gray-1000`으로 바뀌었습니다. 이 토큰을 직접 사용한 화면은 배경과 전경색의 대비를 두 모드에서 확인하고, Solid 배경 위 전경색에는 용도에 맞는 `$color.fg.on-*-solid`를 사용해주세요. 기존 SEED 컴포넌트가 `neutral-inverted`에서 `neutral-solid`로 바꾼 참조는 값이 같아 화면이 그대로이며, ActionButton의 neutral solid 로딩 인디케이터 색만 다크 모드에서 달라집니다.

```tsx
const className = "bg-bg-neutral-solid text-palette-static-white"; // [!code --]
const className = "bg-bg-neutral-solid text-fg-on-neutral-solid"; // [!code ++]
```

<Callout type="warn">
  `--seed-color-bg-neutral-solid` 같은 CSS 변수나 `bg-bg-neutral-solid` 같은 Tailwind 클래스를 하드코딩해 사용했다면 값이 바뀌어도 에러로 잡히지 않습니다. 사용처를 검색해 직접 확인해주세요.
</Callout>

#### 2. Badge의 기본 최대 너비 제거

<Badge tone="critical">직접 판단 필요</Badge>

Badge에 기본으로 적용되던 최대 너비가 제거되었습니다. 2.x의 Rootage 값은 `medium` 7.5rem, `large` 6.75rem이었으며, 이제 긴 라벨이 화면에 더 길게 표시될 수 있습니다. 기존처럼 한 줄 말줄임이 필요한 화면에서는 너비를 직접 지정해주세요.

```tsx
<Badge>길이가 긴 상태 라벨</Badge> // [!code --]
<Badge style={{ maxWidth: "120px" }}>길이가 긴 상태 라벨</Badge> // [!code ++]
```

#### 참고: deprecated 색상 토큰

<Badge tone="critical">직접 판단 필요</Badge>

기존 토큰을 직접 사용했다면 아래처럼 교체해주세요. `$color.bg.neutral-inverted`와 `$color.fg.neutral-inverted`는 `@seed-design/css@4.0.0`에서 제거될 예정입니다. `$color.bg.neutral-inverted-pressed`는 제거 예정이 아니지만 같은 값을 가진 `$color.bg.neutral-solid-pressed`로 함께 교체할 수 있습니다. Solid 배경 위 전경색은 해당 배경에 맞는 `$color.fg.on-*-solid`를 사용하는 것을 권장합니다.

| 기존 토큰 | 대체 토큰 | CSS 변수 변경 |
| --------- | --------- | ------------- |
| `$color.bg.neutral-inverted` | `$color.bg.neutral-solid` | `--seed-color-bg-neutral-inverted` → `--seed-color-bg-neutral-solid` |
| `$color.bg.neutral-inverted-pressed` | `$color.bg.neutral-solid-pressed` | `--seed-color-bg-neutral-inverted-pressed` → `--seed-color-bg-neutral-solid-pressed` |
| `$color.fg.neutral-inverted` | `$color.fg.on-neutral-solid` | `--seed-color-fg-neutral-inverted` → `--seed-color-fg-on-neutral-solid` |

```tsx
const classes = "bg-bg-neutral-inverted active:bg-bg-neutral-inverted-pressed text-fg-neutral-inverted"; // [!code --]
const classes = "bg-bg-neutral-solid active:bg-bg-neutral-solid-pressed text-fg-on-neutral-solid"; // [!code ++]
```

#### 컴포넌트 vars import 교체

**수정 대상:** `@seed-design/css/vars/component` 또는 그 하위 경로에서 vars를 import하는 코드입니다. `@seed-design/css/vars/component/typography`만 사용한다면 이 단계를 건너뛰세요.

<Badge tone="positive">에러로 발견 가능</Badge>

`@seed-design/css/vars/component`에서는 `typography`만 제공합니다. 다른 컴포넌트의 vars는 2.x에서도 SemVer 보장 대상이 아니었으므로, 3.0에서 export를 제거했습니다.

**index에서 `typography`를 가져오는 경우**

`@seed-design/css/vars/component` index를 제거했습니다. `@seed-design/css/vars/component/typography`에서 `vars`를 가져오도록 수정하세요.

```ts
import { typography } from "@seed-design/css/vars/component"; // [!code --]
import { vars as typography } from "@seed-design/css/vars/component/typography"; // [!code ++]
```

**컴포넌트의 vars를 import하는 경우**

같은 값을 [디자인 토큰](/foundations/color)(`@seed-design/css/vars`)에서 찾아 바꾸세요. 토큰을 참조하지 않는 값(`maxWidth: "7.5rem"` 등)은 필요한 값을 직접 지정하세요.

```ts
import { badge } from "@seed-design/css/vars/component"; // [!code --]
import { vars } from "@seed-design/css/vars"; // [!code ++]

const minHeight = badge.sizeMedium.enabled.root.minHeight; // [!code --]
const minHeight = vars.$dimension.x5; // [!code ++]
```

</Step>

<Step>

#### Side Panel 본문의 높이 prop 제거

**수정 대상:** `SidePanelBody` 또는 `ResponsiveSidePanelBody`에 `height`, `minHeight`, `maxHeight`를 전달하는 코드입니다. 이 props를 사용하지 않는다면 이 단계를 건너뛰세요.

<Badge tone="positive">에러로 발견 가능</Badge>

Side Panel 본문은 항상 헤더와 푸터를 제외한 남은 높이를 채웁니다. 세 prop은 효과가 없거나 푸터를 패널 밖으로 밀어내거나 패널 중간에 띄웠기 때문에 제거했습니다.

`SidePanelBody`에서는 해당 prop을 지우세요. `ResponsiveSidePanelBody`에 전달한 높이는 Bottom Sheet로 렌더링될 때만 효과가 있었습니다. 같은 동작이 필요하면 `useResponsiveSidePanelContext()`의 `shouldUseBottomSheet`가 `true`일 때만 본문 안의 `Box`에 높이를 지정하세요.

```tsx
function Body({ children }: { children: React.ReactNode }) {
  const { shouldUseBottomSheet } = useResponsiveSidePanelContext(); // [!code ++]

  return (
    {/* [!code --] */}
    <ResponsiveSidePanelBody minHeight="x40">
    {/* [!code ++] */}
    <ResponsiveSidePanelBody>
      {/* [!code --] */}
      {children}
      {/* [!code ++] */}
      <Box {...(shouldUseBottomSheet && { minHeight: "x40" })}>{children}</Box>
    </ResponsiveSidePanelBody>
  );
}
```

#### 3. Alert Dialog와 Dialog 이름 변경

<Badge tone="critical">직접 판단 필요</Badge>

Alert Dialog와 Dialog의 이름을 snippet의 이름에 맞췄습니다. SEED React 2에서는 `Dialog`가 Alert Dialog를, `ContentDialog`가 Dialog를 가리켰습니다.

| 컴포넌트     | 항목        | SEED React 2                                | SEED React 3                              |
| ------------ | ----------- | ------------------------------------------- | ----------------------------------------- |
| Alert Dialog | React       | `Dialog`                                    | `AlertDialog`                             |
| Alert Dialog | recipe      | `@seed-design/css/recipes/dialog`           | `@seed-design/css/recipes/alert-dialog`   |
| Alert Dialog | class name  | `.seed-dialog__*`                           | `.seed-alert-dialog__*`                   |
| Dialog       | React       | `ContentDialog`                             | `Dialog`                                  |
| Dialog       | recipe      | `@seed-design/css/recipes/content-dialog`   | `@seed-design/css/recipes/dialog`         |
| Dialog       | class name  | `.seed-content-dialog__*`                   | `.seed-dialog__*`                         |
| Dialog       | CSS 변수    | `--content-dialog-*`                        | `--dialog-*`                              |

<Callout type="warn">

`Dialog`, `@seed-design/css/recipes/dialog`, `.seed-dialog__*`는 이름이 그대로 남고 가리키는 대상만 바뀝니다. 기존 Alert Dialog 코드가 에러 없이 Dialog 스타일로 렌더링될 수 있으므로, 모든 항목에서 **Alert Dialog를 먼저** 옮긴 뒤 Dialog를 옮겨주세요.

</Callout>

**snippet을 사용하는 경우**

`seed-design/ui/alert-dialog.tsx`와 `seed-design/ui/dialog.tsx` snippet을 다시 받습니다. snippet이 export하는 `AlertDialogRoot`, `DialogRoot` 등의 이름은 바뀌지 않으므로, snippet을 import하는 코드는 수정하지 않아도 됩니다.

```package-install
npx @seed-design/cli@latest add --on-diff backup ui:alert-dialog ui:dialog
```

**`@seed-design/react`에서 직접 import하는 경우**

1. `Dialog`를 `AlertDialog`로 바꿉니다. `DialogRoot`, `DialogRootProps` 같은 개별 export도 `AlertDialogRoot`, `AlertDialogRootProps`로 바꿉니다.

```tsx
import { Dialog } from "@seed-design/react"; // [!code --]
import { AlertDialog } from "@seed-design/react"; // [!code ++]
```

2. `ContentDialog`를 `Dialog`로 바꿉니다. `ContentDialogRoot`, `ContentDialogRootProps` 같은 개별 export도 `DialogRoot`, `DialogRootProps`로 바꿉니다.

```tsx
import { ContentDialog } from "@seed-design/react"; // [!code --]
import { Dialog } from "@seed-design/react"; // [!code ++]
```

`AlertDialog.Root`는 `role="alertdialog"`와 `closeOnInteractOutside={false}`를 기본값으로 가집니다. 기존에 두 값을 직접 넘기고 있었다면 지워도 됩니다. 바깥을 눌러서 닫혀야 하는 경우에는 `closeOnInteractOutside`를 명시해주세요.

**커스텀 스타일시트에서 selector를 사용 중인 경우**

같은 순서로 class name을 바꿉니다. 먼저 `.seed-dialog__*`를 `.seed-alert-dialog__*`로 바꾼 뒤, `.seed-content-dialog__*`를 `.seed-dialog__*`로 바꿉니다.

```css
/* [!code --] */
.seed-dialog__content {
  /* [!code --] */
  /* ... */
  /* [!code --] */
}
/* [!code ++] */
.seed-alert-dialog__content {
  /* [!code ++] */
  /* ... */
  /* [!code ++] */
}
```

```css
/* [!code --] */
.seed-content-dialog__content {
  /* [!code --] */
  /* ... */
```

#### Headless 컴포넌트·타입 import 교체

**수정 대상:** snippet 밖에서 직접 작성한 코드가 `@seed-design/react/primitive` 또는 독립 headless 패키지를 import하는 경우입니다. 이 import가 다운로드한 snippet 내부에만 있다면, snippet을 업데이트한 뒤 이 단계를 건너뛰세요.

`@seed-design/react/primitive`는 SEED 내부에서 사용하는 headless 컴포넌트를 제공하던 경로입니다. `@seed-design/react`의 SemVer 보장 범위에 포함되지 않아, 내부 구현 변경의 영향을 직접 받을 수 있었습니다. 3.0에서는 이 경로를 제거하고, 사용자에게 필요한 API를 `@seed-design/react`에서 SemVer 보장 범위 내에서 제공합니다. **`@seed-design/react/primitive` import는 반드시 수정하세요.**

독립 headless 패키지를 사용하던 경우에도, `@seed-design/react`에서 기존 동작을 제공하는 API가 있다면 그 경로로 옮기는 것을 권장합니다. headless 컴포넌트와 SEED 스타일 컴포넌트가 상태를 공유하려면 같은 React context를 사용해야 하기 때문입니다. 서로 다른 버전의 headless 패키지를 사용하면 Checkbox의 Control이 Root의 체크 상태를 읽지 못할 수 있습니다. 둘 다 `@seed-design/react`에서 가져오면 같은 내부 구현을 사용하므로 이런 문제를 피할 수 있습니다.

<Callout type="info">
  HTML 요소 wrapper를 제공하는 `@seed-design/react-primitive` 패키지는 이
  마이그레이션의 대상이 아닙니다. 제거된 `@seed-design/react/primitive`와는 다른
  경로이며, 기존 import를 유지하세요.
</Callout>

##### 컴포넌트를 import한 경우

headless Root·Item을 직접 사용했다면 import를 `@seed-design/react`로 바꾸고, 사용하는 컴포넌트와 Props 타입을 아래 표에 따라 교체하세요.

아래의 `.Primitive`와 `List.RadioRoot`는 기존 headless 컴포넌트의 선택·키보드·폼 동작을 제공하면서 SEED 레이아웃 스타일을 추가하지 않습니다. `.Primitive` 없이 `Checkbox.Root`나 `Switch.Root`로 바꾸면 SEED 스타일이 추가되어 직접 작성한 레이아웃이 달라질 수 있습니다.

| 기존 `@seed-design/react/primitive` 컴포넌트      | 변경할 `@seed-design/react` 컴포넌트                                                                                            | Props 타입 변경                                               |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| `Checkbox.Root`                                   | `Checkbox.Root.Primitive`                                                                                                       | `Checkbox.RootProps` → `Checkbox.RootPrimitiveProps`          |
| `RadioGroup.Item`                                 | `RadioGroup.Item.Primitive`                                                                                                     | `RadioGroup.ItemProps` → `RadioGroup.ItemPrimitiveProps`      |
| `RadioGroup.Root` (`RadioGroup.Item`과 함께 사용) | `RadioGroupField.Root.Primitive`. `@seed-design/react`의 `RadioGroup.Root`는 선택 상태를 관리하지 않는 레이아웃 컴포넌트입니다. | `RadioGroup.RootProps` → `RadioGroupField.RootPrimitiveProps` |
| `RadioGroup.Root` (`ListRadioItem`을 감싸는 용도) | `List.RadioRoot`                                                                                                                | `RadioGroup.RootProps` → `List.RadioRootProps`                |
| `Switch.Root`                                     | `Switch.Root.Primitive`                                                                                                         | `Switch.RootProps` → `Switch.RootPrimitiveProps`              |

`ListRadioItem`을 감싼 Root는 사용처의 코드이므로 snippet을 다시 다운로드한 뒤에도 직접 교체하세요.

`Checkbox.HiddenInput`, `RadioGroup.ItemHiddenInput`, `Switch.HiddenInput`은 이름을 유지하고 `@seed-design/react`에서 가져오세요.

```tsx
import { Checkbox } from "@seed-design/react/primitive"; // [!code --]
import { Checkbox } from "@seed-design/react"; // [!code ++]
import { Checkmark } from "seed-design/ui/checkbox";

function CustomCheckbox({ children, ...props }: Checkbox.RootProps) { // [!code --]
function CustomCheckbox({ children, ...props }: Checkbox.RootPrimitiveProps) { // [!code ++]
  return (
    <Checkbox.Root {...props}> // [!code --]
    <Checkbox.Root.Primitive {...props}> // [!code ++]
      {children}
      <Checkmark />
      <Checkbox.HiddenInput />
    </Checkbox.Root> // [!code --]
    </Checkbox.Root.Primitive> // [!code ++]
  );
}
```

Chip·List와 headless 컴포넌트를 `asChild`로 중첩한 코드도 위 import·`.Primitive` 교체 후 구조를 유지할 수 있습니다. `Chip.Root`를 사용했다면 아래 [이름 변경](#chiproot-이름-변경)도 적용하세요.

선택적으로 구조를 간소화하려면 [Chip.Toggle·Chip.RadioItem](/react/components/chip)과 [List.CheckItem·List.RadioItem·List.SwitchItem](/react/components/list)을 참고하세요.

##### Headless Popover를 사용한 경우

**수정 대상:** `@seed-design/react/primitive` 또는 `@seed-design/react-popover`에서 Popover를 가져와 직접 작성한 코드입니다. HelpBubble과 해당 snippet은 내부에서 새 headless Content를 사용하도록 반영되어 있으므로, 기존 사용 코드를 수정할 필요가 없습니다.

기존 headless Popover에 접근성 속성과 포커스 관리를 담당하는 `Popover.Content`가 추가됐습니다. 다음 두 작업을 적용하세요.

1. `@seed-design/react/primitive`에서 가져오던 Popover는 `@seed-design/react-popover`로 import를 바꾸세요. 이미 독립 패키지를 사용했다면 import를 유지하고, 패키지를 `3.0.0` 이상으로 업그레이드하세요.
2. `Popover.Positioner` 또는 `Popover.PositionerPortal` 안의 내용을 `Popover.Content`로 감싸세요. `role="dialog"`와 관련 aria 속성이 Content로 이동했으므로, 직접 지정한 `aria-label`·`aria-labelledby`·`aria-describedby`도 Content에 전달하세요.

```package-install
@seed-design/react-popover@latest
```

```tsx
import { Popover } from "@seed-design/react/primitive"; // [!code --]
import { Popover } from "@seed-design/react-popover"; // [!code ++]

<Popover.Root>
  <Popover.Trigger>열기</Popover.Trigger>
  <Popover.Positioner aria-label="추가 정보"> // [!code --]
  <Popover.Positioner> // [!code ++]
    <Popover.Content aria-label="추가 정보"> // [!code ++]
      <p>내용</p>
    </Popover.Content> // [!code ++]
  </Popover.Positioner>
</Popover.Root>;
```

이번 headless Popover 업데이트에는 다음 동작 변경도 포함됩니다.

- 열릴 때 Content로 포커스를 옮깁니다. 기존처럼 포커스를 유지하려면 Root에 `autoFocus={false}`를 지정하세요.
- 내부에 포커스가 있는 상태에서 닫히면 trigger로 포커스를 돌려줍니다. 내부에서 바깥 요소로 포커스를 옮기면 `closeOnInteractOutside={false}`인 경우를 제외하고 닫히며, 포커스는 그 바깥 요소에 유지됩니다.
- Dialog·Bottom Sheet 안에서 Popover를 여는 경우 Escape나 외부 영역 인터랙션을 통해 두 요소가 동시에 닫히던 문제를 수정했습니다. 이를 피하기 위해 직접 추가했던 이벤트 처리가 있다면 확인하세요.

`@seed-design/react`의 styled `Popover`와 `ui:popover` snippet은 이번 버전에 새로 추가된 [Popover](/react/components/popover) 컴포넌트입니다. 신규 컴포넌트이므로 기존 headless Popover의 교체 대상이 아닙니다.

기존 사용 코드를 수정할 필요는 없지만, 내부 동작 개선을 확인할 수 있는 항목입니다.

#### Help Bubble의 포커스와 닫힘 동작

HelpBubble은 새 headless Content를 내부에서 사용하므로 별도의 마이그레이션이 필요하지 않습니다. 열 때 포커스를 옮기지 않는 기본 동작(`autoFocus={false}`)도 유지됩니다.

Help Bubble 안에 포커스가 있는 상태에서 닫히면 포커스가 trigger로 돌아옵니다. `closeOnInteractOutside={false}`가 아니라면 포커스가 Help Bubble 바깥으로 이동할 때도 닫히며, 이때는 포커스를 옮긴 요소에 그대로 둡니다. Bottom Sheet·Dialog 안에서 Escape나 바깥 누르기로 두 요소가 함께 닫히는 문제를 고쳤으므로 관련 우회 코드와 포커스 이동에 의존하는 동작을 확인해주세요. `HelpBubble.Title`·`HelpBubble.Description`은 이제 Help Bubble의 접근성 이름·설명으로 연결됩니다.
