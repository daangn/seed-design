## 공통 동작

- CLI 실행에는 Node.js 20.19.0 이상이 필요해요.
- `add`, `add-all`은 `seed-design.json` 설정 파일을 사용해요.
- 설정 파일이 없거나 읽을 수 없으면 생성할지 먼저 물어봐요.
- 항목 추가 시 필요한 npm 패키지 의존성은 자동으로 설치돼요.
- `add`, `add-all` 실행 시 스니펫이 요구하는 seed-design 패키지 버전과 현재 프로젝트 버전이 다르면 경고를 보여줘요. (React: `@seed-design/react`, `@seed-design/css` / Lynx: `@seed-design/lynx-react`, `@seed-design/lynx-css`)
- 기존 파일과 내용이 다르면 기본적으로 `덮어쓰기 / 백업 후 교체 / 건너뛰기`를 선택할 수 있어요.
- `--on-diff` 옵션을 주면 충돌 처리 방식을 미리 고정할 수 있어요.
- 실패 원인을 자세히 확인하려면 `--verbose` 옵션을 사용할 수 있어요.


## add

스니펫을 다운로드하고 프로젝트에 추가하는 명령어예요.

<Card icon={<IconFile />} title="Snippet" href="/react/components/concepts/snippet">

자주 쓰이는 UI 패턴의 재사용을 돕는 스니펫에 대해 알아봅니다.

</Card>

```package-install
npx @seed-design/cli@latest add [...item-ids]
```

`item-ids`를 생략하면, 다운로드 가능한 항목을 인터랙티브하게 선택할 수 있어요.

```package-install
npx @seed-design/cli@latest add
```

```sh copy
◆  추가할 항목을 선택해주세요 (스페이스 바로 여러 개 선택 가능)
│  ◻ ui:action-button
│  ◻ ui:alert-dialog
│  ◻ ui:callout
│  ◻ ui:checkbox
│  ◻ ui:switch
│  ◻ ui:text-field
│  ◻ ui:tabs
│  ◻ (deprecated) ui:old-component
│  ◻ ...
└
```

여러 항목을 직접 지정할 수도 있어요.

```package-install
npx @seed-design/cli@latest add ui:action-button ui:alert-dialog
```

### 옵션

| 옵션 | 설명 |
|------|------|
| `-c, --cwd <cwd>` | 작업 디렉토리. 기본값은 현재 디렉토리 |
| `-u, --baseUrl <baseUrl>` | 레지스트리 base URL |
| `--seed-react-version <version>` | 지정한 SEED React 버전의 레지스트리 사용 (예: `1.2`). `--baseUrl`/`--framework`보다 우선 |
| `-f, --framework <framework>` | 대상 프레임워크 (`react` 또는 `lynx`). config의 `framework` 값을 덮어씀 |
| `--on-diff <mode>` | 파일 충돌 처리 방식 지정 (`overwrite` 또는 `backup`) |
| `--verbose` | 실패 시 stack trace 등 상세 오류 정보 출력 |
| `-h, --help` | 도움말 출력 |

### 버전에 맞는 스니펫 받기

프로젝트에 설치된 SEED 패키지 버전과 호환되는 스니펫이 필요하면 버전 옵션을 사용하세요. 해당 버전이 배포된 레지스트리 주소를 CLI가 자동으로 찾아줍니다.

```package-install
npx @seed-design/cli@latest add --seed-react-version 1.2 ui:action-button
```

버전 옵션은 base URL과 프레임워크(react)를 함께 결정하므로 `--baseUrl` / `--framework`보다 우선해요.

#### baseUrl 직접 지정

레지스트리 주소를 직접 지정하려면 `--baseUrl`을 사용하세요. 기본값은 배포 환경 기준 [`https://seed-design.io`](https://seed-design.io)입니다.

```package-install
npx @seed-design/cli@latest add --baseUrl https://v1-2.seed-design.io
```

### 파일 충돌 처리

`--on-diff`를 지정하지 않으면, 기존 파일과 새 스니펫이 다를 때 아래 중 하나를 직접 고를 수 있어요.
- 덮어쓰기
- 기존 파일을 `legacy-<파일명>-<timestamp>`로 백업 후 교체
- 건너뛰기

## add-all

레지스트리 단위로 항목을 한 번에 추가하는 명령어예요.

```package-install
npx @seed-design/cli@latest add-all [...registry-ids]
```

모든 레지스트리의 모든 항목을 추가하려면 `--all` 옵션을 사용하세요.

```package-install
npx @seed-design/cli@latest add-all --all # 모든 레지스트리의 모든 항목 추가
```

특정 레지스트리의 모든 항목을 추가할 수도 있습니다.

```package-install
npx @seed-design/cli@latest add-all breeze # breeze 레지스트리의 모든 항목 추가
```

deprecated 항목을 포함하려면 `--include-deprecated` 옵션을 사용하세요.

```package-install
npx @seed-design/cli@latest add-all ui --include-deprecated # ui 레지스트리의 모든 항목 추가 (deprecated 포함)
```

레지스트리 ID와 `--all`을 모두 생략하면, 추가할 레지스트리를 인터랙티브하게 선택할 수 있어요.

### 옵션

| 옵션 | 설명 |
|------|------|
| `-a, --all` | 모든 레지스트리의 모든 항목 추가 |
| `--include-deprecated` | deprecated 항목 포함 |
| `-c, --cwd <cwd>` | 작업 디렉토리. 기본값은 현재 디렉토리 |
| `-u, --baseUrl <baseUrl>` | 레지스트리 base URL |
| `--seed-react-version <version>` | 지정한 SEED React 버전의 레지스트리 사용 (예: `1.2`). `--baseUrl`/`--framework`보다 우선 |
| `-f, --framework <framework>` | 대상 프레임워크 (`react` 또는 `lynx`). config의 `framework` 값을 덮어씀 |
| `--on-diff <mode>` | 파일 충돌 처리 방식 지정 (`overwrite` 또는 `backup`) |
| `--verbose` | 실패 시 stack trace 등 상세 오류 정보 출력 |
| `-h, --help` | 도움말 출력 |

## compat

현재 프로젝트의 seed-design 패키지 버전과 스니펫 요구 버전이 호환되는지 검사해요. 플랫폼에 따라 검사 대상 패키지가 달라요. (React: `@seed-design/react`, `@seed-design/css` / Lynx: `@seed-design/lynx-react`, `@seed-design/lynx-css`)

```package-install
npx @seed-design/cli@latest compat
```

기본값은 `seed-design.json`의 `path` 아래에 이미 추가된 스니펫만 검사해요.

호환성 이슈가 있으면 종료 코드 `1`, 문제가 없으면 `0`으로 종료돼서 CI/에이전트 환경에서도 바로 사용할 수 있어요.

특정 항목만 검사할 수도 있어요.

```package-install
npx @seed-design/cli@latest compat ui:action-button ui:alert-dialog
```

컴포넌트 shorthand를 쓸 때는 `-c` 옵션을 사용해요.

```package-install
npx @seed-design/cli@latest compat -c action-button -c alert-dialog
```

모든 registry 항목을 검사하려면 `--all`을 사용하세요.

```package-install
npx @seed-design/cli@latest compat --all
```

### 옵션

| 옵션 | 설명 |
|------|------|
| `-c, --component <component>` | 검사할 컴포넌트 ID. 여러 번 또는 쉼표로 지정 가능 |
| `-r, --registry <registryId>` | `--component`에 shorthand를 사용할 때 기본 registry 지정 |
| `-a, --all` | 모든 registry 항목 검사 |
| `--cwd <cwd>` | 작업 디렉토리. 기본값은 현재 디렉토리 |
| `-u, --baseUrl <baseUrl>` | 레지스트리 base URL |
| `-f, --framework <framework>` | 대상 프레임워크 (`react` 또는 `lynx`). config의 `framework` 값을 덮어씀 |
| `--verbose` | 실패 시 stack trace 등 상세 오류 정보 출력 |
| `-h, --help` | 도움말 출력 |

## docs

문서를 나열하고, 찾고, 읽는 명령어예요. 세 개의 하위 명령으로 나뉘어 있어서, 무엇이 돌아올지가
인자의 모양이 아니라 명령 이름으로 정해져요.

| 명령 | 하는 일 |
|------|---------|
| `docs list [주소]` | 그 범위 바로 아래에 무엇이 있는지 한 단계 나열해요 |
| `docs search <질의>` | 이름으로 문서를 찾아 주소를 출력해요 |
| `docs read <주소>` | 그 주소의 문서 본문을 출력해요 |

`docs`만 입력하면 하위 명령 안내를 stderr로 내보내고 종료 코드 `1`로 끝나요. 뒤에 붙은 값을
주소로 해석하지 않아요.

세 명령 모두 순수 텍스트로 출력하므로 LLM 파이프나 스크립트에 그대로 넘길 수 있어요. 작업
디렉토리와 프로젝트 설정 파일을 읽지 않기 때문에, 같은 입력은 어디서 실행하든 같은 문서를
가리켜요.

### 주소 문법

주소는 문서 사이트 주소에서 도메인만 뺀 값이고, 세 명령이 같은 문법을 공유해요.

| 형태 | 뜻 | 결과 |
|------|----|------|
| `/react/components/action-button` | 고정 주소. 경로 전체와 완전히 일치해요 | 0개 또는 1개 |
| `action-button` | 꼬리 질의. 경로의 마지막 조각들과 일치해요 | 0개 이상 |
| `react/` | 범위. 그 아래 전부예요 | 0개 이상 |

앞의 슬래시가 고정 주소와 짧게 친 이름을 갈라요. 문서 경로 51개가 다른 문서 경로의 꼬리라서,
`components/bottom-sheet`처럼 그 자체로 완전한 경로도 꼬리 규칙만으로는 여러 문서에 걸리거든요.

뒤의 슬래시는 컨테이너와, 같은 자리에 있는 문서를 갈라요. `/react`는 React 카테고리의 개요
문서이고, `react/`는 그 카테고리가 담고 있는 것들이에요.

## docs list

그 범위 바로 아래에 무엇이 있는지 한 단계만 나열해요. 주소를 생략하면 최상위부터 보여줘요.

```package-install
npx @seed-design/cli@latest docs list
```

```sh copy
/ai-integration/   4개 항목
/breeze/           2개 항목
/components/      62개 항목
/docs/             2개 항목
/foundations/     20개 항목
/lynx/            32개 항목
/patterns/         1개 항목
/react/          109개 항목
/updates/          5개 항목
```

범위를 좁혀 가면 그 아래를 이어서 볼 수 있어요.

```sh copy
npx @seed-design/cli@latest docs list react/              # react가 담은 것들
npx @seed-design/cli@latest docs list react/components/   # 그 아래 문서들
```

줄 끝의 슬래시가 그 줄을 다음에 어느 명령으로 넘길지 알려줘요. 슬래시로 끝나면 컨테이너라서
`docs list`로 한 단계 더 들어가고, 슬래시가 없으면 문서라서 `docs read`로 읽어요.

```sh copy
/react/components/action-button  Action Button
/react/components/bottom-sheet   Bottom Sheet
/react/components/concepts/      3개 항목
```

카테고리는 문서 사이트의 최상위 섹션과 같아요. `get-started`, `foundations`, `components`,
`patterns`, `docs`, `react`, `breeze`, `lynx`, `ai-integration`, `updates`를 쓸 수 있어요.

<Callout type="info">
  `components`는 **디자인 스펙**(Anatomy, Properties, Guidelines) 카테고리예요.
  React 구현 문서는 `react/components` 아래에 있어요.

  ```sh
  # 디자인 스펙
  npx @seed-design/cli@latest docs read /components/action-button

  # React 구현
  npx @seed-design/cli@latest docs read /react/components/action-button
  ```
</Callout>

## docs search

이름과 제목으로 문서를 찾아 주소를 출력해요.

```package-install
npx @seed-design/cli@latest docs search action-button
```

```sh copy
/components/action-button
/components/floating-action-button
/components/reaction-button
/react/components/action-button
/react/components/floating-action-button
/react/components/reaction-button
/lynx/components/action-button
/updates/whats-new-in-action-button
```

문서 id와 제목 양쪽에서 대소문자를 무시하고 부분 일치를 찾아요. 결과가 여러 개인 것은
정상이라서 종료 코드는 `0`이고, 하나도 없을 때만 `1`이에요.

stdout에는 한 줄에 주소 하나씩만 나가고, 찾은 개수는 stderr로 나가요. 그래서
`docs search sheet | head`처럼 주소만 이어 쓸 수 있어요.

출력된 주소는 `docs read`가 그대로 받는 값이에요. 이름으로 찾아서 주소로 읽는 흐름이 그래서
두 명령으로 이어져요.

```sh copy
npx @seed-design/cli@latest docs search checkbox
npx @seed-design/cli@latest docs read /lynx/components/checkbox
```

## docs read

주소가 가리키는 문서의 본문을 stdout으로 출력해요.

```package-install
npx @seed-design/cli@latest docs read /react/components/action-button
```

```sh copy
# Action Button
URL: /react/components/action-button
Source: https://github.com/daangn/seed-design/blob/dev/docs/content/react/components/action-button.mdx

명확한 액션을 쉽게 수행할 수 있도록 돕는 기본 인터랙션 컴포넌트입니다.

사용 가능 버전: @seed-design/react@0.0.1, @seed-design/css@0.0.1

## Preview
...
```

stdout에는 사이트가 준 바이트만 나가요. 구분자와 머리말을 포함해서 CLI가 만든 문자는 한 글자도
섞이지 않아요.

패키지 changelog처럼 문서 목록에 없는 주소도 가져올 수 있어요.

```package-install
npx @seed-design/cli@latest docs read /react/updates/changelog/react/1.2.5
```

<Callout type="info">
  스니펫 원본은 `add` 명령으로 받아요. 레지스트리를 거치므로 의존성과 버전이 함께 맞춰져요.

  ```sh
  npx @seed-design/cli@latest add ui:action-button
  ```
</Callout>

### 여러 문서를 가리켰을 때

`action-button` 같은 꼬리 질의는 여러 문서에 걸려요. `docs read`는 그중 하나를 고르지 않고
후보를 알려준 뒤 종료 코드 `1`로 끝나요. 잘못된 문서를 조용히 받아서 그것을 근거로 작업하는
것이 가장 나쁜 결과이기 때문이에요.

```sh copy
$ npx @seed-design/cli@latest docs read action-button
문서 조회에 실패했어요.
원인: action-button: 여러 문서를 가리켜요.

   - /components/action-button
   - /react/components/action-button
   - /lynx/components/action-button

해결 힌트: 앞에 슬래시를 붙인 전체 주소를 그대로 넣으면 하나로 좁혀져요.
```

같은 후보 목록이 `docs search`에서는 stdout에 실려요. 어느 스트림에 있느냐가 그것이 답인지
아닌지를 말해줘요.

## 스트림과 종료 코드

`docs`의 세 명령은 다른 명령어와 달리 터미널 장식을 그리지 않아요. 파이프로 넘기거나 그대로
다시 입력하기 위한 출력이라서예요.

| 스트림 | 담는 것 |
|--------|---------|
| stdout | 질의에 대한 답만 담아요 |
| stderr | 그 밖의 전부예요. 실패 이유, 후보 목록, 찾은 개수, 텔레메트리 안내가 모두 여기로 가요 |

| 코드 | 의미 |
|------|------|
| `0` | stdout에 답이 있어요 |
| `1` | 그 밖의 전부예요. 이유는 stderr에 있어요 |

### 옵션

세 하위 명령이 같은 옵션을 받아요.

| 옵션 | 설명 |
|------|------|
| `-u, --baseUrl <baseUrl>` | 문서 사이트 base URL |
| `--verbose` | 실패 시 stack trace 등 상세 오류 정보 출력 |
| `-h, --help` | 도움말 출력 |

## 이전 버전에서 옮겨오기

| 지금까지 | 앞으로 |

하위 명령 없는 형태는 남겨 두지 않았어요. 무엇을 요청하는지가 이름에 드러나지 않는 호출을
없애는 것이 이 변경의 목적이라서, 하위 호환을 위해 예전 형태를 유지하면 그 목적이 사라져요.
