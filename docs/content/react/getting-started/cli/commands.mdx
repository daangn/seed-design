## 공통 동작

- `add`, `add-all`은 `seed-design.json` 설정 파일을 사용해요.
- 설정 파일이 없거나 읽을 수 없으면 생성할지 먼저 물어봐요.
- 항목 추가 시 필요한 npm 패키지 의존성은 자동으로 설치돼요.
- `add`, `add-all` 실행 시 스니펫이 요구하는 seed-design 패키지 버전과 현재 프로젝트 버전이 다르면 경고를 보여줘요. (React: `@seed-design/react`, `@seed-design/css` / Lynx: `@seed-design/lynx-react`, `@seed-design/lynx-css`)
- 기존 파일과 내용이 다르면 기본적으로 `덮어쓰기 / 백업 후 교체 / 건너뛰기`를 선택할 수 있어요.
- `--on-diff` 옵션을 주면 충돌 처리 방식을 미리 고정할 수 있어요.
- 실패 원인을 자세히 확인하려면 `--verbose` 옵션을 사용할 수 있어요.

## add

스니펫을 다운로드하고 프로젝트에 추가하는 명령어예요.

<Card icon={<IconFile />} title="Snippet" href="/react/components/concepts/snippet">

자주 쓰이는 UI 패턴의 재사용을 돕는 스니펫에 대해 알아봅니다.

</Card>

```package-install
npx @seed-design/cli@latest add [...item-ids]
```

`item-ids`를 생략하면, 다운로드 가능한 항목을 인터랙티브하게 선택할 수 있어요.

```package-install
npx @seed-design/cli@latest add
```

```sh copy
◆  추가할 항목을 선택해주세요 (스페이스 바로 여러 개 선택 가능)
│  ◻ ui:action-button
│  ◻ ui:alert-dialog
│  ◻ ui:callout
│  ◻ ui:checkbox
│  ◻ ui:switch
│  ◻ ui:text-field
│  ◻ ui:tabs
│  ◻ (deprecated) ui:old-component
│  ◻ ...
└
```

여러 항목을 직접 지정할 수도 있어요.

```package-install
npx @seed-design/cli@latest add ui:action-button ui:alert-dialog
```

### 옵션

| 옵션 | 설명 |
|------|------|
| `-c, --cwd <cwd>` | 작업 디렉토리. 기본값은 현재 디렉토리 |
| `-u, --baseUrl <baseUrl>` | 레지스트리 base URL |
| `--seed-react-version <version>` | 지정한 SEED React 버전의 레지스트리 사용 (예: `1.2`). `--baseUrl`/`--framework`보다 우선 |
| `-f, --framework <framework>` | 대상 프레임워크 (`react` 또는 `lynx`). config의 `framework` 값을 덮어씀 |
| `--on-diff <mode>` | 파일 충돌 처리 방식 지정 (`overwrite` 또는 `backup`) |
| `-a, --all` | **Deprecated**. 현재는 에러를 출력하고 `add-all` 사용을 안내 |
| `--verbose` | 실패 시 stack trace 등 상세 오류 정보 출력 |
| `-h, --help` | 도움말 출력 |

### 버전에 맞는 스니펫 받기

프로젝트에 설치된 SEED 패키지 버전과 호환되는 스니펫이 필요하면 버전 옵션을 사용하세요. 해당 버전이 배포된 레지스트리 주소를 CLI가 자동으로 찾아줍니다.

```package-install
npx @seed-design/cli@latest add --seed-react-version 1.2 ui:action-button
```

버전 옵션은 base URL과 프레임워크(react)를 함께 결정하므로 `--baseUrl` / `--framework`보다 우선해요.

#### baseUrl 직접 지정

레지스트리 주소를 직접 지정하려면 `--baseUrl`을 사용하세요. 기본값은 배포 환경 기준 [`https://seed-design.io`](https://seed-design.io)입니다.

```package-install
npx @seed-design/cli@latest add --baseUrl https://v1-2.seed-design.io
```

### 파일 충돌 처리

`--on-diff`를 지정하지 않으면, 기존 파일과 새 스니펫이 다를 때 아래 중 하나를 직접 고를 수 있어요.
- 덮어쓰기
- 기존 파일을 `legacy-<파일명>-<timestamp>`로 백업 후 교체
- 건너뛰기

## add-all

레지스트리 단위로 항목을 한 번에 추가하는 명령어예요.

```package-install
npx @seed-design/cli@latest add-all [...registry-ids]
```

모든 레지스트리의 모든 항목을 추가하려면 `--all` 옵션을 사용하세요.

```package-install
npx @seed-design/cli@latest add-all --all # 모든 레지스트리의 모든 항목 추가
```

특정 레지스트리의 모든 항목을 추가할 수도 있습니다.

```package-install
npx @seed-design/cli@latest add-all breeze # breeze 레지스트리의 모든 항목 추가
```

deprecated 항목을 포함하려면 `--include-deprecated` 옵션을 사용하세요.

```package-install
npx @seed-design/cli@latest add-all ui --include-deprecated # ui 레지스트리의 모든 항목 추가 (deprecated 포함)
```

레지스트리 ID와 `--all`을 모두 생략하면, 추가할 레지스트리를 인터랙티브하게 선택할 수 있어요.

### 옵션

| 옵션 | 설명 |
|------|------|
| `-a, --all` | 모든 레지스트리의 모든 항목 추가 |
| `--include-deprecated` | deprecated 항목 포함 |
| `-c, --cwd <cwd>` | 작업 디렉토리. 기본값은 현재 디렉토리 |
| `-u, --baseUrl <baseUrl>` | 레지스트리 base URL |
| `--seed-react-version <version>` | 지정한 SEED React 버전의 레지스트리 사용 (예: `1.2`). `--baseUrl`/`--framework`보다 우선 |
| `-f, --framework <framework>` | 대상 프레임워크 (`react` 또는 `lynx`). config의 `framework` 값을 덮어씀 |
| `--on-diff <mode>` | 파일 충돌 처리 방식 지정 (`overwrite` 또는 `backup`) |
| `--verbose` | 실패 시 stack trace 등 상세 오류 정보 출력 |
| `-h, --help` | 도움말 출력 |

## compat

현재 프로젝트의 seed-design 패키지 버전과 스니펫 요구 버전이 호환되는지 검사해요. 플랫폼에 따라 검사 대상 패키지가 달라요. (React: `@seed-design/react`, `@seed-design/css` / Lynx: `@seed-design/lynx-react`, `@seed-design/lynx-css`)

```package-install
npx @seed-design/cli@latest compat
```

기본값은 `seed-design.json`의 `path` 아래에 이미 추가된 스니펫만 검사해요.

호환성 이슈가 있으면 종료 코드 `1`, 문제가 없으면 `0`으로 종료돼서 CI/에이전트 환경에서도 바로 사용할 수 있어요.

특정 항목만 검사할 수도 있어요.

```package-install
npx @seed-design/cli@latest compat ui:action-button ui:alert-dialog
```

컴포넌트 shorthand를 쓸 때는 `-c` 옵션을 사용해요.

```package-install
npx @seed-design/cli@latest compat -c action-button -c alert-dialog
```

모든 registry 항목을 검사하려면 `--all`을 사용하세요.

```package-install
npx @seed-design/cli@latest compat --all
```

### 옵션

| 옵션 | 설명 |
|------|------|
| `-c, --component <component>` | 검사할 컴포넌트 ID. 여러 번 또는 쉼표로 지정 가능 |
| `-r, --registry <registryId>` | `--component`에 shorthand를 사용할 때 기본 registry 지정 |
| `-a, --all` | 모든 registry 항목 검사 |
| `--cwd <cwd>` | 작업 디렉토리. 기본값은 현재 디렉토리 |
| `-u, --baseUrl <baseUrl>` | 레지스트리 base URL |
| `-f, --framework <framework>` | 대상 프레임워크 (`react` 또는 `lynx`). config의 `framework` 값을 덮어씀 |
| `--verbose` | 실패 시 stack trace 등 상세 오류 정보 출력 |
| `-h, --help` | 도움말 출력 |

## doctor

> 실험적 기능이에요. 룰과 출력 형식이 바뀔 수 있어요.

프로젝트가 SEED를 어떻게 쓰고 있는지 진단해요. 문제만 지적하는 게 아니라 **왜 중요한지, 어떤 문서를 읽어야 하는지, 어떻게 바꾸는지**를 함께 알려줘요. seed-design.io가 서빙하는 최신 지식(컴포넌트 스펙, deprecation, 스니펫 registry)을 기준으로 삼기 때문에, 문서가 갱신되면 진단 결과도 따라서 최신이 돼요.

```package-install
npx @seed-design/cli@latest doctor
```

경로를 지정해 검사 범위를 좁힐 수 있어요.

```package-install
npx @seed-design/cli@latest doctor src/pages
```

### 룰

룰은 **판정을 무엇이 하느냐**로 나뉘어요. 두 종류 모두 같은 모양의 가이드(맥락·참조 문서·수정 방법)를 제공해요.

**결정론 룰** — 코드로 판정해요. 항상 같은 결과가 나오므로 CI 게이트와 집계에 쓸 수 있어요.

| 룰 | 기본 심각도 | 설명 |
|------|------|------|
| `seed/no-deprecated-component` | warn | deprecated 컴포넌트 import와 설치된 deprecated 스니펫을 감지해요 |
| `seed/valid-variant` | error | 최신 컴포넌트 스펙에 없는 variant 값 사용을 감지해요 |
| `seed/snippet-generation` | info | 설치된 스니펫이 구버전 세대인지 알려줘요 |

**에이전트 룰** — 판단이 필요해 코드로는 못 푸는 영역이에요. doctor는 LLM을 호출하지 않고 검토 요청 문서만 만들고, 실행은 여러분의 에이전트가 해요. `--fail-on` 게이트와 심각도 집계에서는 제외돼요.

| 룰 | 설명 |
|------|------|
| `seed/component-usage-review/{component}` | 컴포넌트 사용이 디자인 가이드라인에 맞는지 검토를 요청해요 |

이 룰은 **판정 기준을 들고 있지 않아요.** 기준은 각 컴포넌트의 [디자인 가이드라인 문서](/components)에 있고, 에이전트가 그걸 읽어서 도출해요 — Guidelines 절의 규범 문장과 Do/Don't 캡션이 각각 하나의 기준이 돼요. 그래서 **가이드라인 문서가 좋아지면 진단도 같이 좋아지고**, 가이드라인이 아직 없는 컴포넌트는 검토 대상에서 조용히 빠져요.

### 에이전트에게 넘기기

`--prompt`는 결정론 룰이 알아낸 **사실**과 에이전트에게 위임할 **검토 요청**을 한 문서로 만들어요. 참조 문서 링크와 판정 기준이 함께 담기므로, 그 문서만 에이전트에 붙여넣으면 바로 작업할 수 있어요.

```package-install
npx @seed-design/cli@latest doctor --prompt
```

### CI에서 사용하기

`--fail-on` 기준(기본 `error`) 이상의 문제가 있으면 종료 코드 `1`, 없으면 `0`으로 종료돼요.

```package-install
npx @seed-design/cli@latest doctor --fail-on warn
```

`--json`을 사용하면 스키마 버저닝된 JSON 리포트를 출력해요. 억제된 finding도 `suppressed: true`로 포함돼요.

```package-install
npx @seed-design/cli@latest doctor --json
```

### 특정 위치 억제하기

정당한 사유가 있는 코드는 주석 디렉티브로 억제할 수 있어요. 사유를 함께 남기는 걸 권장해요.

```tsx
// seed-doctor-ignore-next-line seed/no-deprecated-component -- 2.0 마이그레이션 진행 중
import { Fab } from "@seed-design/react";
```

같은 줄에 붙일 수도 있어요: `// seed-doctor-ignore <rule-id> -- <사유>`

룰 전체를 끄거나 심각도를 바꾸려면 [seed-doctor.json 설정](/react/getting-started/cli/configuration)을 사용하세요.

### 옵션

| 옵션 | 설명 |
|------|------|
| `[...paths]` | 검사할 파일·디렉토리. 생략하면 현재 디렉토리 전체 |
| `--cwd <cwd>` | 작업 디렉토리. 기본값은 현재 디렉토리 |
| `-u, --baseUrl <baseUrl>` | 지식을 가져올 base URL |
| `-f, --framework <framework>` | 대상 프레임워크 (`react` 또는 `lynx`). config의 `framework` 값을 덮어씀 |
| `--json` | 결과를 JSON으로 출력 (사람용 출력 억제) |
| `--prompt` | 에이전트에게 넘길 마크다운 출력 — 사실 + 검토 요청 (사람용 출력 억제) |
| `--fail-on <level>` | 종료 코드 `1` 기준 심각도 (`error`, `warn`, `info`, `never`). 기본값 `error` |
| `--verbose` | 실패 시 stack trace 등 상세 오류 정보 출력 |
| `-h, --help` | 도움말 출력 |

## docs

문서 링크, llms.txt 링크, 스니펫 링크를 조회하는 명령어예요.

```package-install
npx @seed-design/cli@latest docs [query]
```

`query`를 생략하면, 카테고리 → 섹션 → 항목을 인터랙티브하게 선택할 수 있어요.

```package-install
npx @seed-design/cli@latest docs
```

```sh copy
◆  카테고리를 선택해주세요
│  React
│
◆  섹션을 선택해주세요
│  컴포넌트
│
◆  항목을 선택해주세요
│  Action Button
│
│  action-button
│  - docs: https://seed-design.io/react/components/action-button
│  - llms.txt: https://seed-design.io/llms/react/components/action-button.txt
│  - snippet: https://raw.githubusercontent.com/daangn/seed-design/refs/heads/dev/docs/registry/react/ui/action-button.tsx
│
```

### 직접 검색

항목 이름으로 직접 검색할 수 있어요.

```package-install
npx @seed-design/cli@latest docs action-button
```

### 경로 기반 검색

`카테고리/섹션/항목` 형태로 직접 경로를 지정할 수 있어요.

```package-install
npx @seed-design/cli@latest docs react/components/action-button
```

카테고리만 지정하면 해당 카테고리의 섹션/항목을 선택할 수 있어요.

```package-install
npx @seed-design/cli@latest docs react
```

카테고리/섹션까지 지정하면 해당 섹션의 항목을 선택할 수 있어요.

```package-install
npx @seed-design/cli@latest docs react/components
```

### 오타 제안

경로에 오타가 있으면 유사한 유효 경로를 제안해줘요.

```sh copy
react/component/action-buton: 문서를 찾을 수 없어요.

💡 이것을 의미했나요?
   - react/components/action-button
```

### Raw 모드

`--raw` 옵션을 사용하면 UI 없이 llms.txt 내용을 순수 마크다운으로 출력해요. LLM 파이프나 스크립트에서 활용할 수 있어요.

```package-install
npx @seed-design/cli@latest docs react/components/action-button --raw
```

패키지 changelog도 가져올 수 있어요.

```package-install
npx @seed-design/cli@latest docs react/updates/changelog/react/1.2.5 --raw
```

### 옵션

| 옵션 | 설명 |
|------|------|
