## 소개

[`@seed-design/docs-mcp`](https://github.com/daangn/seed-design/tree/dev/packages/docs-mcp)는 SEED 문서를 위한 공식 MCP(Model Context Protocol) 서버입니다.

이 MCP 서버를 사용하면 AI Agent가 다음 정보에 직접 접근할 수 있습니다:

- **컴포넌트**: 해부도, 속성, 사용 가이드라인
- **React · Lynx · Breeze**: 설치, props, 사용 예시
- **Foundations**: 색상, 타이포그래피, 간격 등 디자인 토큰
- **Rootage**: 디자인 토큰과 컴포넌트 스펙 원본 데이터

Figma 연결 없이 독립적으로 실행되며, SEED를 사용하는 프로젝트에서 AI 도구의 문서 이해도를 높일 수 있습니다.

## 조회할 문서 사이트 바꾸기

기본값은 `https://seed-design.io`입니다. `SEED_DOCS_BASE_URL` 환경 변수로 로컬 문서 서버나 아카이브 사이트를 겨눌 수 있습니다. MCP 클라이언트 설정에서 `env`로 넘깁니다.

```json
{
  "mcpServers": {
    "seed-docs": {
      "command": "npx",
      "args": ["-y", "@seed-design/docs-mcp"],
      "env": { "SEED_DOCS_BASE_URL": "http://localhost:3000" }
    }
  }
}
```

## 사용 가능한 도구

서버가 등록하는 도구는 다섯 개입니다.

섹션 목록은 서버 안에 상수로 들어 있지 않고, 문서 사이트가 게시하는 인덱스를 호출 시점에 읽어옵니다. 사이트 구조가 바뀌면 이미 설치된 버전도 그대로 따라가므로, 섹션 이름을 외워서 넘기는 대신 `discover_seed_docs`로 현재 목록을 먼저 확인하세요.

### Discovery

#### `discover_seed_docs`

문서 사이트가 게시하는 섹션과 카테고리 구조를 반환합니다. 섹션마다 문서 개수와 접근 가능한 엔드포인트가 함께 실립니다.

**파라미터:** 없음

**예시:**
```
discover_seed_docs()
```

**예시 응답 (발췌):**
```json
{
  "totalSections": 10,
  "sections": [
    {
      "id": "components",
      "name": "Components",
      "documentCount": 61,
      "categories": [
        { "id": "components", "name": "Components", "documentCount": 61 }
      ],
      "endpoints": { "overview": "/components/llms.txt" }
    },
    {
      "id": "react",
      "name": "React",
      "documentCount": 110,
      "categories": [
        { "id": "getting-started", "name": "Getting Started", "documentCount": 11 },
        { "id": "components", "name": "Components", "documentCount": 82 }
      ],
      "endpoints": {
        "overview": "/react/llms.txt",
        "full": "/react/llms-full.txt"
      }
    }
  ]
}
```

`endpoints`에 `full`이 있는 섹션만 `get_full_docs`를 지원합니다.

---

### 문서

#### `list_docs`

섹션 안의 문서 목록을 카테고리별로 묶어 반환합니다. 각 항목에 `get_doc`으로 넘길 `path`와 설명, deprecated 표시가 함께 나옵니다.

**파라미터:**
| 이름 | 타입 | 설명 |
|------|------|------|
| `section` | string | 섹션 id. `discover_seed_docs`로 현재 목록을 확인합니다 |
| `category` | string (선택) | 섹션 안의 카테고리 필터 (예: `components`) |

**예시:**
```
list_docs({ section: "react", category: "components" })
```

**예시 응답:**
```
# React Documentation

Total: 82 documents (filtered by: components)

### components

  - Accordion (path: components/accordion) — 여러 개의 관련된 콘텐츠 섹션을 수직으로 나열하고, 각 섹션을 펼치거나 접어 정보를 탐색할 수 있는 컴포넌트입니다.
  - Action Button (path: components/action-button) — 명확한 액션을 쉽게 수행할 수 있도록 돕는 기본 인터랙션 컴포넌트입니다.
  ...

## Usage

Use get_doc with section="react" and a path above to read a document.
```

없는 섹션을 넘기면 실제 섹션 목록을 담아 거부하므로, 한 번의 재시도로 바로잡을 수 있습니다.

#### `get_doc`

특정 문서의 본문을 반환합니다.

**파라미터:**
| 이름 | 타입 | 설명 |
|------|------|------|
| `section` | string | 섹션 id |
| `path` | string | 섹션 기준 상대 경로 (예: `components/action-button`, `color`) |

**예시:**

컴포넌트의 디자인 스펙:
```
get_doc({ section: "components", path: "action-button" })
```

같은 컴포넌트의 React API:
```
get_doc({ section: "react", path: "components/action-button" })
```

파운데이션 문서:
```
get_doc({ section: "foundations", path: "color" })
```

이름만 넘겼는데 그 이름을 가진 문서가 섹션 안에 둘 이상이면, 앞의 것을 돌려주지 않고 후보 경로를 담아 거부합니다. `react` 섹션의 `alert-dialog`, `bottom-sheet`, `menu-sheet`가 여기에 해당하므로 `components/` 또는 `stackflow/`까지 붙여서 넘겨야 합니다.

#### `get_full_docs`

섹션의 모든 문서를 하나의 텍스트로 합쳐 반환합니다. 전체 문서를 게시하는 섹션에서만 동작하고, 그렇지 않은 섹션에서는 `list_docs`를 안내합니다.

**파라미터:**
| 이름 | 타입 | 설명 |
|------|------|------|
| `section` | string | 섹션 id |

**예시:**
```
get_full_docs({ section: "react" })
```

---

### Rootage

SEED의 Rootage 스펙(디자인 토큰 및 컴포넌트 스펙의 원본 JSON 데이터)에 접근합니다.

#### `get_rootage`

Rootage 리소스를 반환합니다. 경로 없이 호출하면 사용 가능한 모든 리소스 목록을 반환합니다.

**파라미터:**
| 이름 | 타입 | 설명 |
|------|------|------|
| `path` | string (선택) | 리소스 경로 (예: `/color.json`, `/components/action-button.json`) |

**예시:**

리소스 목록 조회:
```
get_rootage()
```

특정 리소스 조회:
```
get_rootage({ path: "/components/action-button.json" })
```

경로는 인덱스와 대조한 뒤 가져오므로, `/rootage` 밖을 가리키는 값은 거부됩니다.

## 프로그래매틱 사용

`@seed-design/docs-mcp`는 npm 패키지로 설치하여 커스텀 MCP 서버에 통합할 수 있습니다.

### 설치

`server`는 MCP TypeScript SDK v2의 `McpServer` 인스턴스이므로, transport를 직접 연결하려면 `@modelcontextprotocol/server`도 함께 설치합니다.

```bash
npm install @seed-design/docs-mcp @modelcontextprotocol/server
# 또는
bun add @seed-design/docs-mcp @modelcontextprotocol/server
```

### 사용 예시

```javascript
import { StdioServerTransport } from "@modelcontextprotocol/server/stdio";
import { server } from "@seed-design/docs-mcp/server";
import { initializeTools } from "@seed-design/docs-mcp/tools";

// 도구 초기화
initializeTools(server);

// 원하는 transport와 함께 사용 (stdio, Streamable HTTP 등)
await server.connect(new StdioServerTransport());
```

## 개발

로컬에서 개발하거나 테스트할 때 사용하는 명령어입니다.

```bash
# 의존성 설치
bun install

# 개발 모드 실행 (stdio)
bun run dev

# 빌드
bun run build

# 린트
bun run lint

# 타입 검사
bun run typecheck
```

### MCP Inspector로 테스트

[MCP Inspector](https://github.com/modelcontextprotocol/inspector)를 사용하면 브라우저에서 도구를 테스트할 수 있습니다:

```bash
npx @modelcontextprotocol/inspector bun ./dist/stdio.js
```
