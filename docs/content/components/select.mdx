## Anatomy

<FigmaImage
  id="2279:5133"
  alt="Select의 Anatomy 이미지. Trigger, Content, Item으로 구성됩니다."
/>

Select는 트리거와 콘텐츠 두 레이어로 구성됩니다. 트리거는 현재 선택값을 보여주고, 콘텐츠는 선택 가능한 옵션 목록을 펼쳐서 보여줍니다.

- **Trigger**: 선택값 또는 placeholder를 표시하고, 클릭하면 Content를 엽니다.
- **Content**: 트리거에 anchor된 floating 패널로 옵션 목록을 펼쳐 보여줍니다. 너비를 Trigger에 맞춥니다.
- **Item**: Content 내부 옵션 하나를 표현하며 label, description을 가집니다. suffix icon으로 선택 상태를 나타내므로 prefix icon만 변경 가능합니다.
- **Group**: Content 내부에서 관련 있는 Item을 묶는 단위입니다. Group Label로 제목을 붙일 수 있습니다.
- **Divider**: Group 간의 시각적 경계를 짓는 구분선입니다. Item 간에는 Divider를 사용하지 않으며 모든 Group 간에 표시됩니다.

## Properties

### Size

<FigmaImage id="2279:5167" alt="Select의 Size Property - Large, Medium" />

Select는 Large, Medium 두 가지 사이즈로 제공됩니다.

- **Large**: 모바일·데스크탑 어디서나 사용할 수 있습니다. [Input Button](/components/input-button)의 Large와 동일합니다.
- **Medium**: Breakpoint `lg` 이상(데스크탑)에서만 사용합니다. 모바일에서는 사용하지 않습니다.

### State

#### Select State

- **Open**: 콘텐츠가 열려 있는 상태입니다. suffix의 chevron이 위로 회전합니다.

#### Trigger State

<FigmaImage
  id="2279:5185"
  alt="Select Trigger의 State - Enabled, Pressed, Error, Error Pressed, Disabled, Read Only"
/>

- **Enabled**: 기본 상태입니다. 사용자가 선택할 수 있습니다.
- **Pressed**: 트리거를 누르고 있는 동안의 상태입니다.
- **Error**: 폼 검증 실패 시의 상태입니다. 트리거 stroke가 critical 색으로 강조됩니다.
- **Error Pressed**: Error 상태에서 트리거를 누르고 있는 동안의 상태입니다.
- **Disabled**: 비활성 상태입니다. 사용자가 상호작용할 수 없습니다.
- **Read Only**: 값을 보여주지만 변경할 수 없는 상태입니다.

#### Content Item State

<FigmaImage
  id="2279:5198"
  alt="Select Content Item의 State - Enabled, Pressed, Selected, Disabled"
/>

- **Enabled**: 기본 상태입니다.
- **Pressed**: 옵션을 누르고 있는 동안의 상태입니다.
- **Selected**: 현재 선택된 옵션입니다. indicator 자리에 checkmark가 표시됩니다.
- **Disabled**: 비활성 상태입니다. 선택할 수 없습니다.

### Has Prefix Icon

<FigmaImage
  id="2279:5219"
  alt="Select의 Has Prefix Icon Property - Trigger와 Item에 Prefix Icon을 적용한 예시"
/>

트리거 좌측에 prefix 아이콘을 표시할 수 있습니다. 필드의 의미를 시각적으로 강조하고 싶을 때 사용합니다.

Prefix Icon이 있는 Item 1개가 선택된 경우, Trigger Prefix 사용 여부와 무관하게 선택된 Item의 Prefix Icon을 항상 Trigger Prefix로 표시합니다. 2개 이상이 선택된 경우 Trigger Prefix Icon을 표시합니다.

## Guidelines

### 선택 컴포넌트 사용하기

<FigmaImage
  id="2279:5312"
  alt="타임존 선택 화면에서 Radio/Checkbox와 Select의 사용 상황을 비교한 예시"
/>

<FigmaImage
  id="2279:5350"
  alt="Select Box와 Chip의 사용 상황을 비교한 예시"
/>

선택지의 개수와 보조 설명 여부에 따라 컴포넌트를 선택합니다. 아래 순서대로 판단합니다.

1. 보조 설명이나 이미지가 필요한 경우 [Select Box](/components/select-box)를 사용합니다. 카드 형태로 항상 펼쳐져 있어 옵션을 비교하며 고를 수 있습니다.
2. 선택지가 5개 이상인 경우 Select를 사용합니다. 목록을 접어 두어 공간을 절약할 수 있으며, 그룹으로 묶어 구조화할 수 있습니다.
3. 선택지가 2~4개이고 설명이 불필요한 경우 [Radio Group](/components/radio)/[Checkbox](/components/checkbox)를 사용합니다. 모든 옵션이 한눈에 보여 선택이 빠릅니다.
4. 라벨이 길지 않은 경우 [Chip](/components/chip)을 사용합니다. 가로로 나열해 가볍게 고를 수 있습니다.

선택지가 매우 많아 스크롤만으로 탐색하기 어렵다면 검색형 선택(Combobox) 패턴이 더 적합합니다. Combobox는 Select와 인터랙션 모델이 다른 별개의 컴포넌트이며, 현재 SEED에서는 제공하지 않습니다.

### 단일 선택과 다중 선택

Select는 값을 하나만 고르는 단일 선택이 기본이며, 여러 값을 고르는 다중 선택도 지원합니다.

단일 선택에서는 옵션을 고르는 즉시 콘텐츠가 닫히고, 이미 선택된 옵션을 다시 눌러도 값이 그대로 유지됩니다. 다중 선택에서는 옵션을 골라도 콘텐츠가 닫히지 않아 여러 값을 이어서 고를 수 있고, 이미 선택된 옵션을 다시 누르면 선택이 해제됩니다.

### 옵션 순서

목록의 순서는 사용자가 옵션을 판단하는 순서를 따릅니다. 아직 고르기 전의 상태를 뜻하는 옵션은 맨 앞에, 나머지를 모두 보고 나서야 고르게 되는 옵션은 맨 뒤에 둡니다. 그 사이의 옵션은 사용 빈도나 크기·시간처럼 그 목록에 자연스러운 기준으로 정렬합니다.

나머지와 성격이 다른 옵션은 별도 Group으로 분리합니다. Group이 둘 이상이면 사이에 Divider가 자동으로 표시되어 경계가 드러납니다. 옵션 하나만 담은 Group에는 Group Label을 붙이지 않습니다. 라벨을 붙이면 옵션 하나가 카테고리처럼 보입니다.

### 고르지 않은 상태 설계하기

단일 선택 Select는 이미 고른 옵션을 다시 눌러도 해제되지 않으므로, 값을 되돌릴 수단은 옵션 목록 안에 두어야 합니다. 이 수단이 없으면 사용자는 원하지 않는 값을 남겨 두거나 폼을 포기하게 됩니다. placeholder는 값이 아직 없다는 것을 알려주는 라벨일 뿐, 값을 비우는 수단이 아닙니다.

목록에 무엇을 둘지는 그 필드에서 "고르지 않음"이 값인지 아닌지에 따라 정합니다.

- **값을 비우는 옵션**: "아직 고르지 않았음"을 뜻합니다. 목록 맨 앞에 두고 값은 비워 둡니다. 이 옵션을 고른 상태는 아무것도 고르지 않은 상태와 같은 값으로 제출되므로, 두 상태를 구분해 다루지 않습니다. 라벨을 placeholder와 같은 문구로 쓰면 화면에서도 두 상태가 같아 보여 혼란이 없습니다.
- **"없음"을 뜻하는 옵션**: "없음", "모르겠음"처럼 그 자체가 하나의 답입니다. 값은 비워 두지 않고 실제 값을 부여합니다. 값을 비워 두면 아무것도 고르지 않은 상태와 구분되지 않아 필수 필드에서 검증에 실패합니다. 목록 맨 뒤에 별도 Group으로 둡니다.

"없음"을 뜻하는 옵션의 라벨은 질문의 핵심을 되풀이해 작성합니다. "해당 없음"처럼 화면상의 위치를 가리키는 표현은 화면 낭독기 사용자에게 전달되지 않으므로 쓰지 않습니다. 예를 들어 "하자가 있나요?"라는 질문에는 "하자 없음"이라고 씁니다.

필드의 성격에 따라 다음과 같이 조합합니다.

- **하나를 반드시 골라야 하는 필드**: Field에 필수 표시를 하고, 값을 비우는 옵션은 두지 않습니다. 아무것도 고르지 않은 상태로 제출하면 검증에 실패합니다.
- **"고르지 않음"도 답으로 받아야 하는 필드**: Field에 필수 표시를 하고, "없음"을 뜻하는 옵션을 실제 값으로 목록 맨 뒤에 둡니다. 사용자가 질문을 건너뛴 것인지 없다고 답한 것인지 구분해야 할 때 이렇게 합니다. 답을 강제하는 만큼 이탈이 늘 수 있으므로, 두 답변을 구분해야 할 이유가 분명할 때만 사용합니다.
- **비워 두어도 되는 필드**: Field에 필수 표시를 하지 않고, 값을 비우는 옵션을 목록 맨 앞에 둡니다. 이 옵션이 없으면 실수로 고른 사용자가 값을 되돌릴 수 없어, 필수가 아닌 필드가 사실상 필수처럼 동작합니다.
- **값이 항상 채워져 있는 설정성 필드**: 정렬 기준, 알림 주기처럼 값이 비어 있을 수 없는 필드에는 값을 비우는 옵션을 두지 않고 기본값을 미리 선택해 둡니다. 반대로 사용자에게 답을 묻는 필드에는 기본값을 미리 선택해 두지 않습니다. 미리 선택된 값은 사용자가 질문을 지나쳤다는 사실을 알아채지 못하게 하고, 답이 아닌 값이 그대로 제출되게 만듭니다.

### 다중 선택 사용하기

다중 선택에서는 이미 고른 옵션을 다시 누르면 해제되므로, 값을 비우는 옵션을 따로 두지 않습니다.

- **고를 수 있는 개수를 안내합니다**: 옵션을 몇 개까지 고를 수 있는지 컨트롤의 생김새만으로는 알기 어렵습니다. Field의 설명글에 "모두 선택", "최대 3개 선택"처럼 명시하고, 최소·최대 개수 제한이 있다면 조건을 만족했는지 화면에서 바로 알 수 있게 합니다.
- **한 번에 지울 수단을 함께 둡니다**: 옵션을 하나씩 다시 눌러 해제하는 것만으로는 되돌리기 어렵고, 화면 낭독기나 키보드로는 더 어렵습니다. Select 자체에는 전체 해제 기능이 없으므로, [Field](/components/field) Header의 Suffix Slot에 "초기화" [Ghost Button](/components/action-button)을 두는 식으로 Select 바깥에 배치합니다.
- **"없음"을 뜻하는 옵션은 다른 옵션과 함께 고를 수 없게 합니다**: 이 옵션을 고르면 나머지 선택이 모두 해제되고, 나머지를 고르면 이 옵션이 해제됩니다. 특정 옵션만 다르게 동작하는 것은 예측하기 어려우므로, "없음"이 정말 답으로 필요할 때만 둡니다. 옵션을 둘지 여부와 라벨, 위치는 단일 선택과 같습니다.
- **전체 선택은 옵션 목록 안에 넣지 않습니다**: 목록 안의 항목 하나가 나머지를 모두 바꾸는 동작은 예측하기 어렵습니다. 전체 선택이 자주 쓰이는 필드라면 부모 [Checkbox](/components/checkbox)를 제공하는 Checkbox Group이 더 적합합니다. 필터처럼 전부 고른 상태와 아무것도 고르지 않은 상태의 결과가 같은 화면에서는 전체 선택 자체를 두지 않습니다.
- **최소 1개 이상 골라야 한다면 Field에 필수 표시를 합니다**: 아무것도 고르지 않은 상태로 제출하면 검증에 실패하게 하고, 오류 문구는 무엇을 골라야 하는지 그대로 적습니다.

옵션은 사용자가 한눈에 구분할 수 있도록 명사형으로 작성합니다. 옵션 간에 일관된 어휘·길이·톤을 유지합니다.

옵션이 길어 한 줄로 표시되지 않으면 옵션 라벨 자체를 줄이는 것을 먼저 고려하고, 줄이기 어려울 때만 description을 활용해 보조 설명을 둘째 줄로 분리합니다.

콘텐츠의 옵션 라벨은 잘리지 않고 줄바꿈되지만, 트리거의 선택값과 placeholder는 한 줄로 표시되어 트리거 너비를 넘으면 말줄임표로 잘립니다. 목록에서는 다 보이던 라벨이 트리거에서는 잘릴 수 있으므로, 옵션 라벨은 트리거 너비 안에 들어가는 길이로 정합니다.

라벨을 줄일 수 없다면 트리거에 표시할 형태를 따로 정합니다.

다중 선택은 선택값을 쉼표로 이어 붙여 보여주므로 특히 잘리기 쉽습니다. 선택값이 트리거 너비를 넘는 시점부터 [빈칸]처럼 개수로 요약합니다.

/>

사용자가 트리거를 클릭하면 콘텐츠가 트리거 아래쪽에 떠오릅니다. 화면 하단에 공간이 부족하면 위쪽으로 자동 전환됩니다.

옵션을 클릭하면 트리거 라벨이 선택값으로 바뀌고 콘텐츠는 닫힙니다.

콘텐츠 바깥을 클릭하면 선택을 반영하지 않고 콘텐츠가 닫힙니다. 이미 선택되어 있던 값은 그대로 유지됩니다.

콘텐츠가 열려 있는 동안 현재 선택된 옵션에는 indicator 자리에 checkmark가 표시됩니다. 선택된 옵션이 목록 아래쪽에 있어도 그 옵션이 보이는 위치로 스크롤된 상태에서 열립니다.

### 목록 길이

콘텐츠의 높이는 최대 480px과 트리거 주변에 남은 화면 공간 중 더 작은 값으로 정해지고, 옵션이 그보다 많으면 콘텐츠 안에서 스크롤됩니다. 화면이 좁아도 최소 높이는 확보되므로, 옵션이 많은 Select는 목록 안에서 스크롤되는 상태를 기본으로 두고 설계합니다.

## Menu vs. Select

<FigmaImage id="2279:5656" alt="Menu와 Select를 비교한 예시" />

[Menu](/components/menu)는 동작을 실행하는 명령 목록이고, Select는 폼에서 값을 고르는 컨트롤입니다.

Select에는 필드 라벨이 있고 고른 값은 저장하기 전까지 반영되지 않지만, Menu에는 필드 라벨이 없고 항목을 누르면 즉시 실행됩니다.

항목을 고른 뒤 저장 또는 제출 버튼을 눌러야 한다면 Select입니다.
