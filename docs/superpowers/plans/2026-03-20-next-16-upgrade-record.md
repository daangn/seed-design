# Next.js 16 Upgrade — Implementation Record

> Completed 2026-03-20. Branch: `feat/next-16-upgrade`

**Goal:** Upgrade docs site from Next.js 15.5.9 → 16.2.0, fumadocs-ui 15.8.5 → 16.6.17.

**Architecture:** Uses `--webpack` flag for both dev and build because Turbopack lacks custom export condition support (`seed-layered`). All template-literal dynamic imports migrated to static registries or kept as-is (server-only webpack-safe patterns).

---

## What Changed

### 1. Package Versions
- `next`: 15.5.9 → 16.2.0
- `fumadocs-ui`: 15.8.5 → 16.6.17
- `fumadocs-core`: 16.4.3 → 16.6.17
- `fumadocs-mdx`: 14.2.5 → 14.2.10
- Added `next-themes` as direct dependency (was only transitive via fumadocs-ui)

### 2. Scripts (`docs/package.json`)
- `dev`: added `--webpack` flag (Next.js 16 defaults to Turbopack, which can't handle `seed-layered` condition)
- `build`: added `--webpack` flag
- Added `generate:example-registry` script
- Added to `generate:all` pipeline

### 3. Client-Side Dynamic Import Migration
**Problem:** `import(\`../examples/${name}.tsx\`)` pattern is fragile — webpack builds glob-based chunks but Turbopack can't analyze template literals. This was a likely cause of the previous page hangs.

**Solution:** Created a static registry (`docs/components/example-registry.ts`) mapping 427 example names to explicit import functions. Auto-generated by `docs/scripts/generate-example-registry.ts`.

**Files changed:**
- `docs/components/component-preview.tsx` — uses `getExampleComponent(name)` from registry
- `docs/components/stackflow-preview.tsx` — same (note: takes `names: string[]`, maps over them)
- `docs/app/blocks/[name]/block-renderer.tsx` — simplified to `notFound()` (block directory is empty)

### 4. Server-Side Dynamic Imports (kept as-is)
**Attempted:** Replacing `import(\`@/public/rootage${path}\`)` with `fs.readFileSync`.
**Reverted:** Because `rootage.ts` exports pure functions (`stringifyVariants`, etc.) that are imported by client-bundled components (`component-variant-table.tsx`). Adding `node:fs` to the file caused webpack to try bundling Node.js built-ins for the browser.

The original dynamic import pattern works fine with webpack's tree-shaking. These patterns will need revisiting only when migrating to Turbopack.

**Server-only files** (`manual-installation.tsx`, `breeze-manual-installation.tsx`) — also kept original dynamic imports for consistency.

### 5. Fumadocs v16 API Changes
- **Provider import path**: `fumadocs-ui/provider` → `fumadocs-ui/provider/next` (6 files)
- **ThemeToggle removed**: Created local `docs/components/theme-toggle.tsx` using `next-themes` (used in one MDX page for demo)
- **ImageZoom type**: React 19.2 added `Blob` to `img.src` types, which conflicts with Next.js `Image` component. Fixed by extracting `src` and filtering to `string` only.
- **MdxJsxFlowElement data type**: `_string` property no longer in type definition. Fixed with type assertion.

### 6. Async Params (no changes needed)
All page/layout files already use `Promise<...>` typed params with `await` — no migration required.

## Turbopack Limitation (Future Work)

Turbopack does **not** support custom Node.js package export conditions. The `@seed-design/css` package uses a `seed-layered` condition:
```json
"./recipes/*": {
  "seed-layered": { "import": "./recipes/*.layered.mjs" },
  "default": { "import": "./recipes/*.mjs" }
}
```

Available Turbopack config options (`root`, `rules`, `resolveAlias`, `resolveExtensions`, `debugIds`) do not include condition resolution. Tracked in [Next.js discussions #77721](https://github.com/vercel/next.js/discussions/77721).

**Options when Turbopack adds support:**
1. Remove `--webpack` flags, add `turbopack: { resolveConditions: ["seed-layered"] }`
2. Or change `@seed-design/css` to make layered the default export
