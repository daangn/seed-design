# 루프 학습 (지식 환원)

ship의 두 번째 핵심. 이번 세션에서 겪은 마찰과 얻은 지식을, 다음 세션이 다시 헤매지 않도록 **영구 자산(AGENTS.md·메모리)으로 환원**한다. 에이전트는 매 세션 cold하게 시작하므로, 적어두지 않으면 매번 같은 곳에서 막힌다. 적어두면 compound된다.

단 *"loop가 매끄러울수록 이해가 썩는다"*. 반영은 자동이 아니라 **제안 → 사용자 승인 → 별도 커밋**이다.

## 언제 — 마찰·남길 지식이 있을 때만

이번 세션(및 이어진 다른 세션)에 다음이 있었으면 수행, 없으면 스킵:
- 리뷰가 반복 지적한 패턴
- AGENTS.md/TECH.md에 없어서 추측하거나 사용자가 정정해준 맥락
- 우회·막힘이 발생한 지점
- `/changeset` 등 연계 스킬이 어색했던 지점

## 절차

1. **마찰·지식 수집** — 위 항목을 모은다.
2. **원인 귀속** (maker ≠ checker) — 각 항목이 어디 부족해서 생겼는지 가른다. ship을 실행한 맥락은 자기 평가에 관대하므로, 큰 판단이면 **별도 서브에이전트**에 맡긴다:
   - AGENTS.md/TECH.md 맥락 부족 → 어느 파일
   - ship/`create-component`/`changeset` 스킬 결함 → 어디
3. **stale 검증 (늘리기 전에 정리)** — 보강하려는 문서의 기존 줄을 실제 코드와 대조한다. outdated·모순 줄을 함께 정리한다. 문서는 추가만 하지 않는다 — 매 사이클 줄만 늘면 신뢰를 잃는다.
4. **환원 대상 구분**:
   - **AGENTS.md** — 팀이 공유할 actionable 룰. `self-documentation` 컨벤션을 따른다(컨벤션은 AGENTS.md, 기술 상세는 TECH.md, 디버깅 히스토리·배경은 넣지 않음). nested 계층: 상위는 얕고 넓게, 하위는 깊고 좁게.
   - **메모리** — 개인 맥락·선호·프로젝트 진행 상황(레포에 커밋하지 않을 것).
5. **제안 → 승인 → 별도 커밋** — 회고를 `[부족점 / 귀속처 / stale 정리 / 제안 diff]`로 보여준다. 승인하면 `docs(agents): ...` 등 **코드 PR과 분리된 커밋**으로 반영한다. 거절하면 반영하지 않는다.

## 주의

- 자동 반영 금지(comprehension debt 방지).
- 추가는 stale 정리와 짝으로. 이미 있는 룰을 중복 추가하지 않는다.
- 일반 상식 룰(any 금지, 미사용 import 등)은 모델이 이미 알고 레포 `CLAUDE.md`가 이미 주입하므로 **굳이 적지 않는다.** 적을 가치가 있는 건 *레포 고유의 비자명한* 룰뿐이다.
