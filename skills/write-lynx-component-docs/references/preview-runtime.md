# 문서 미리보기와 Lynx 런타임

## 실행 주소 규칙

미리보기 매니페스트의 native bundle 경로를 현재 origin 기준의 절대 HTTP(S) URL로 만든다. `fullscreen=true`처럼 런타임에 필요한 쿼리를 이 주소에 붙인다.

- QR 코드: 절대 `.lynx.bundle` URL을 그대로 인코딩한다.
- 주소 복사: 같은 `.lynx.bundle` URL을 사용한다.
- Explorer 실행 버튼: `lynx://open?url=<인코딩한 bundle URL>` 형식의 딥 링크를 사용한다.

QR 코드에 `lynx://` 딥 링크를 넣지 않는다. Lynx Explorer가 QR에서 직접 bundle URL을 읽는 흐름과 버튼으로 앱을 여는 흐름을 구분한다.

실기기에서는 개발 컴퓨터의 `localhost`나 `127.0.0.1`에 접근할 수 없다. QR 실행을 확인할 때 기기에서 접근 가능한 LAN 주소나 배포 주소인지 함께 확인한다.

## 웹과 네이티브의 차이

WebLynx 미리보기는 문서에서 빠르게 구조와 기본 상호작용을 확인하는 수단이다. 네이티브 렌더링 결과를 보증하지 않는다.

다음 항목은 실제 Lynx Explorer 또는 PlayLynx에서 확인한다.

- `tint-color` 같은 네이티브 전용 스타일
- 이미지 디코딩과 아이콘 착색 결과
- 네이티브 CSS 파서가 처리하는 shorthand와 CSS 변수
- 기기별 레이아웃과 이벤트 동작

웹과 네이티브 결과가 다르면 먼저 차이를 문서 미리보기의 한계로 분류할 수 있는지 확인한다. 실제 호스트 앱에서도 같은 사용법으로 재현될 때만 컴포넌트 또는 런타임 문제로 본다.

## 디버깅 순서

1. 문서 미리보기에서 예제 엔트리와 로드된 CSS를 확인한다.
2. native bundle을 다시 빌드하고 QR 코드의 원문 URL을 확인한다.
3. 같은 bundle을 Lynx Explorer 또는 PlayLynx에서 실행한다.
4. Lynx DevTool에서 연결된 client와 session을 찾는다.
5. 대상 노드의 트리, 계산된 스타일, box model을 확인한다.
6. 소스 코드, 생성 bundle, 초기 렌더링 값을 비교한다.
7. 문서 도구, 예제 코드, 컴포넌트, Lynx 런타임 중 어느 계층의 문제인지 결정한다.

DevTool에서 런타임에 주입한 스타일은 ReactLynx의 초기 렌더링 경로와 다르게 처리될 수 있다. 동적 스타일 변경 결과 하나만으로 초기 렌더링의 지원 여부를 단정하지 않는다.

## CSS shorthand와 변수

리터럴 값은 작동하지만 `var(...)`를 포함한 shorthand가 `0px`로 계산되면 다음을 확인한다.

1. shorthand 파서가 CSS 변수를 해석하기 전에 유효하지 않은 길이로 확정하는지 확인한다.
2. 대응하는 longhand가 CSS 변수 해석 경로를 보존하는지 확인한다.
3. 한 축만 지정했을 때 줄바꿈이나 방향 전환에서 의미가 달라지지 않는지 확인한다.
4. 실제 호스트 앱에서도 재현되는 경우 컴포넌트 구현에서 의미가 같은 longhand 조합으로 해결한다.

예를 들어 단일 `gap` 값을 대체할 때는 레이아웃 방향과 무관하게 같은 의미를 유지하도록 `row-gap`과 `column-gap`을 함께 검토한다. 문서 예제에만 숫자 간격을 넣어 런타임 문제를 가리지 않는다.

## 아이콘 색상

아이콘 노드가 렌더링됐지만 보이지 않으면 다음을 구분한다.

- 자산이 로드되지 않았다.
- 크기나 레이아웃이 0이다.
- base CSS가 컴포넌트의 아이콘 스타일을 덮었다.
- 네이티브 `tint-color`가 웹 미리보기에서 적용되지 않았다.
- 실제 네이티브 환경에서도 착색이 실패했다.

먼저 import 순서와 계산된 스타일을 확인한다. 웹에서만 색상이 보이지 않고 네이티브에서 정상이라면 컴포넌트를 수정하지 말고 문서에 확인 방법을 안내한다. 네이티브에서도 실패하면 실제 컴포넌트 또는 런타임 문제로 분리한다.
