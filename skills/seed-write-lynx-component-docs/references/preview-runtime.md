# 문서 미리보기와 Lynx 런타임

## 실행 주소 규칙

미리보기 매니페스트의 native bundle 경로를 현재 origin 기준의 절대 HTTP(S) URL로 만든다. `fullscreen=true`처럼 런타임에 필요한 쿼리를 이 주소에 붙인다.

- QR 코드: 절대 `.lynx.bundle` URL을 그대로 인코딩한다.
- 주소 복사: 같은 `.lynx.bundle` URL을 사용한다.
- Explorer 실행 버튼: `lynx://open?url=<인코딩한 bundle URL>` 형식의 딥 링크를 사용한다.

QR 코드에 `lynx://` 딥 링크를 넣지 않는다. Lynx Explorer가 QR에서 직접 bundle URL을 읽는 흐름과 버튼으로 앱을 여는 흐름을 구분한다.

실기기에서는 개발 컴퓨터의 `localhost`나 `127.0.0.1`에 접근할 수 없다. QR 실행을 확인할 때 기기에서 접근 가능한 LAN 주소나 배포 주소인지 함께 확인한다.

## 브라우저 미리보기와 실제 Lynx의 차이

브라우저 미리보기는 문서에서 구조와 기본 상호작용을 빠르게 확인하는 수단이다. 실제 Lynx 렌더링 결과를 보증하지 않는다.

다음 항목은 실제 Lynx Explorer 또는 PlayLynx에서 확인한다.

- `tint-color` 같은 네이티브 전용 스타일
- 이미지 디코딩과 아이콘 착색 결과
- 네이티브 CSS 파서가 처리하는 shorthand와 CSS 변수
- 기기별 레이아웃과 이벤트 동작

웹과 네이티브 결과가 다르면 먼저 차이를 문서 미리보기의 한계로 분류할 수 있는지 확인한다. 실제 호스트 앱에서도 같은 사용법으로 재현될 때만 컴포넌트 또는 런타임 문제로 본다.

## 오버레이 예제의 미리보기 높이

BottomSheet처럼 화면 전체를 기준으로 배치되는 오버레이 예제는 자동 높이를 사용하지 않는다. 자동 높이에서는 닫힌 상태의 트리거 콘텐츠만 `lynx-view` 높이에 반영되어, 오버레이를 열었을 때 Positioner가 지나치게 작은 화면을 기준으로 배치될 수 있다.

이 경우 문서의 `LynxComponentExample`에 콘텐츠를 확인하기 충분한 `height`를 명시한다. 미리보기 탭 안에서 다음 항목을 함께 확인한다.

- 닫힌 상태의 예제가 지정한 높이를 모두 사용한다.
- Backdrop과 Positioner가 `lynx-view` 전체 높이를 채운다.
- 열린 Content가 미리보기 카드 바깥의 문서 본문을 덮지 않는다.
- 작은 문서 폭에서도 가로 스크롤이나 잘린 액션이 생기지 않는다.

고정 높이는 문서 미리보기의 화면 크기를 정하는 용도다. 이를 위해 배포 컴포넌트의 Positioner나 Content 스타일을 바꾸지 않는다.

문서 미리보기 런타임은 `lynx-view`를 초기화하기 전에 `transformVW`를 활성화한다. 고정 높이 미리보기는 `transformVH`도 활성화한다. 그래야 예제의 `vw`와 `vh`가 브라우저 창이 아니라 개별 미리보기 영역을 기준으로 계산된다. 이 설정이 빠지면 `width: 100vw`인 오버레이가 미리보기 카드 너비를 넘어가고, `vh` 기반 높이와 이동 거리도 카드 높이와 어긋난다.

자동 높이 미리보기에서는 `transformVH`를 비활성화한다. 브라우저 미리보기 런타임은 `transformVH`가 활성화된 `lynx-view`에 크기 격리를 적용하므로, `height: auto`와 함께 사용하면 콘텐츠로부터 높이를 계산하지 못해 `0px`이 될 수 있다. `vh`가 필요한 오버레이 예제는 `LynxComponentExample`에 높이를 명시한다.

오버레이가 Lynx Explorer에서는 정상인데 문서 미리보기에서만 넘친다면 다음 순서로 확인한다.

1. 고정 높이 미리보기에서는 `transformVW`와 `transformVH`, 자동 높이 미리보기에서는 `transformVW`가 bundle URL을 설정하기 전에 활성화됐는지 확인한다.
2. 열린 Content의 너비가 `lynx-view` 너비와 같은지 확인한다.
3. 작은 문서 폭에서도 Content의 좌우 경계가 `lynx-view` 경계 안에 있는지 확인한다.

예제 CSS에서 `vw`를 `%`로 바꾸거나 오버레이 너비를 강제로 덮어써서 문서 미리보기만 맞추지 않는다. 네이티브와 문서가 같은 viewport 단위를 사용하도록 미리보기 런타임을 구성한다.

## 미리보기와 런타임의 책임

일반적인 문서 작업에서는 실제 문서의 `LynxComponentExample`과 생성 bundle만 조사한다. 브라우저 미리보기 문제를 독립 HTML이나 임시 앱으로 옮기지 않는다. `docs/out`에서도 같은 실패가 재현되고 문서 도구의 책임을 구분해야 할 때만 별도 진단 범위를 검토한다.

실제 Lynx 동작을 확인해야 하면 사용 가능한 호스트 앱이나 `examples/lynx-spa`에서 대상 예제를 직접 실행한다. 확인한 기기·실행 환경과 결과를 기록하되, 특정 개발 도구의 세션 조작 절차를 이 문서에 고정하지 않는다.

기기나 기존 session이 없으면 네이티브 검증이 환경에 의해 차단됐다고 보고한다. 문서 예제에 네이티브 동작을 흉내 내는 코드나 별도 실행 환경을 추가하지 않는다. DevTool에서 주입한 동적 스타일 하나만으로 초기 렌더링의 지원 여부를 단정하지 않는다.

## CSS shorthand와 변수

리터럴 값은 작동하지만 `var(...)`를 포함한 shorthand가 `0px`로 계산되면 다음을 확인한다.

1. shorthand 파서가 CSS 변수를 해석하기 전에 유효하지 않은 길이로 확정하는지 확인한다.
2. 대응하는 longhand가 CSS 변수 해석 경로를 보존하는지 확인한다.
3. 한 축만 지정했을 때 줄바꿈이나 방향 전환에서 의미가 달라지지 않는지 확인한다.
4. 실제 호스트 앱에서도 재현되는 경우 컴포넌트 구현에서 의미가 같은 longhand 조합으로 해결한다.

예를 들어 단일 `gap` 값을 대체할 때는 레이아웃 방향과 무관하게 같은 의미를 유지하도록 `row-gap`과 `column-gap`을 함께 검토한다. 문서 예제에만 숫자 간격을 넣어 런타임 문제를 가리지 않는다.

## 아이콘 색상

아이콘 노드가 렌더링됐지만 보이지 않으면 다음을 구분한다.

- 자산이 로드되지 않았다.
- 크기나 레이아웃이 0이다.
- base CSS가 컴포넌트의 아이콘 스타일을 덮었다.
- 네이티브 `tint-color`가 웹 미리보기에서 적용되지 않았다.
- 실제 네이티브 환경에서도 착색이 실패했다.

먼저 import 순서와 계산된 스타일을 확인한다. 웹에서만 색상이 보이지 않고 네이티브에서 정상이라면 컴포넌트를 수정하지 말고 문서에 확인 방법을 안내한다. 네이티브에서도 실패하면 실제 컴포넌트 또는 런타임 문제로 분리한다.
