터미널이 없으면 프롬프트를 띄우는 대신 기본값으로 진행하거나 명시적으로 실패합니다.

지금까지 CI나 AI 코딩 에이전트처럼 터미널이 없는 환경에서 `init`, `add`, `add-all`을 실행하면, 답을 받을 수 없는 프롬프트 앞에서 아무 일도 하지 않은 채 종료 코드 `0`으로 끝났습니다. 표준 입력이 파이프로 열려 있는 경우에는 대신 끝나지 않고 멈춰 있었습니다. 성공했다고 말하지만 파일은 하나도 바뀌지 않은 상태였습니다.

이제 표준 입력과 표준 출력이 **둘 다** 터미널일 때만 프롬프트가 뜹니다. 그렇지 않으면 미리 답해 둘 인자가 있는 경우 그 값을 쓰고, 없으면 어떤 인자를 넘기면 되는지 알려준 뒤 종료 코드 `2`로 끝납니다.

| 프롬프트가 뜨던 상황 | 터미널이 없을 때 |
|---|---|
| `init`의 다섯 가지 질문 | 기본값으로 파일을 만듭니다. `-y`를 붙인 것과 같습니다 |
| `seed-design.json`이 없을 때 | `seed-design init -y`를 먼저 실행하라고 알려줍니다 |
| `add`에 항목을 넘기지 않았을 때 | 항목을 인자로 넘기라고 알려줍니다 |
| `add`에 넘긴 항목이 deprecated일 때 | `--include-deprecated`를 함께 넘기라고 알려줍니다 |
| `add-all`에 레지스트리도 `--all`도 없을 때 | 사용 가능한 레지스트리 목록을 알려줍니다 |
| 기존 파일과 내용이 다를 때 | 그 파일을 그대로 두고 경로를 알려줍니다 |

옵션 두 개가 늘었습니다.

- `add --include-deprecated`: `add-all`에만 있던 옵션입니다. deprecated 항목을 묻지 않고 추가합니다.
- `--on-diff skip`: 기존 파일을 그대로 두고 새 파일만 받습니다. 이제 대화형 선택지 세 가지를 모두 인자로 쓸 수 있습니다.

터미널에서 직접 쓰던 방식은 그대로입니다. 항목 선택기도, 파일 충돌 선택지도 지금까지와 똑같이 뜹니다.

확인이 필요한 경우는 두 가지입니다.

터미널 없이 이 명령들을 돌리던 스크립트는 지금까지 종료 코드 `0`을 받고 있었지만 실제로는 아무 일도 일어나지 않았습니다. 이제 그 자리에서 `2`를 받게 되므로, 무엇을 넘겨야 하는지 stderr를 확인하고 인자를 채워 주세요.

그리고 `add`를 `--on-diff` 없이 표준 입력을 닫고 실행해서 파일을 바꾸지 않고 차이만 확인하던 용법은 더 이상 `0`으로 끝나지 않습니다. 같은 목적이라면 `--on-diff skip`을 사용해 주세요.
