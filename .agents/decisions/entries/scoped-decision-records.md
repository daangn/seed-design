# 선택의 이유는 lesson과 분리해 경로별로 조회한다

## 결정과 적용 조건

- `.agents/decisions/entries/`를 결정 기록 위치로 두고 해당 AGENTS에서 조회·상태·기록 절차를 관리한다. 루트 시작 절차와 Karpathy Skill이 관련 결정을 선택해 계획에 반영하도록 연결한다.
- lesson은 확인된 경험의 원인·조건·다음 행동, decision은 방향 선택·대안·비용·확정 근거를 보존한다. 관련 기록은 링크하며 본문을 중복하지 않는다.
- 적용 조건이 맞는 확정 결정만 계획의 기준으로 쓴다. 제안은 합의로 취급하지 않고, 기존 선택과 달라지는 판단은 근거와 함께 사람에게 연결한다.

## 배경·대안·비용

- PR과 기여자가 늘면서 과거 선택이 개인 기억이나 PR에 흩어져 후속 계획이 같은 기준을 따르기 어렵다.
- PR에만 남기면 검색과 적용 조건 판별이 어렵다. lesson에 모두 합치면 관찰된 사실과 사람이 선택한 정책을 혼동할 수 있다.
- 기존 learnings와 같은 metadata·entries 방식은 좁게 조회할 수 있지만, 결정 상태와 근거가 현재 규칙과 맞는지 유지하는 비용이 생긴다. 모든 과거 결정을 일괄 이관하지 않는다.

## 확정 근거와 재검토

- 확정 근거: 2026-10-06 사용자 명시 요청. “.agents에 learnings와 같은 구조로 decisions가 있어야” 하며 루트 AGENTS와 계획·결정 기록 절차를 연결하도록 요청했다. 이 요청은 기록 구조의 도입 근거이며 다른 도메인 정책의 합의를 대신하지 않는다.
- 담당자: 별도 유지 담당자는 미정이다. 후속 구조 변경은 요청자 또는 관련 영역 담당자와 판단한다.
- 현재 구현은 조회·기록 지침이다. 자동 로딩, 새 에이전트의 실제 선택, lint·CI 강제를 검증한 상태는 아니다.
- 재검토 조건: 조회 누락, 중복 기록, 서로 충돌하는 확정 결정, 관리 비용이 반복되면 검색 방식·필드·담당 체계를 재검토한다.
